# T-58 — тождество сущности: сделано, признано неверным, отложено

**Фаза:** 1 · **SP:** 2 · **RICE:** 4.2 · **Статус:** ⏸ (отложена, не отменена)

**Критерий приёмки** — `uv run pytest tests/test_entities.py -q`
(тесты зелёные; отложена не из-за них, а из-за неверной модели — см. ниже)

## Что было не так

«МТС» — не одна сущность с вариантами написания. Проверка сравнивала имя
**подстрокой**, и строка «оператор: МТС Беларусь» подтверждала утверждение про
«МТС»: `support = 1.000`, `confirmed` — измерено на
`project/data/telecom_open_metrics.csv`.

## Что сделано

- снимок страницы значений `knowledge/raw/2026-11-09/` + запись манифеста
  (`url`, `retrieved`, `kind: meanings`, `title`, `sha256`, CC BY-SA 4.0);
- `pf.meanings` разбирает перечень прочтений и читает страну;
- `pf.entities` сравнивает наборы прочтений утверждения и источника и отдаёт
  долю, вид исхода, причину и ссылку;
- `pf.ground.field_verdict` — три состояния: неоднозначность **понижает**
  подтверждение и не отменяет отказ (`support_without_subject`);
- `_cap_by_readings` — дословная цитата тоже проверяется прочтениями;
- виды `entity-ambiguous` / `entity-mismatch` в `pf.verdicts.KINDS`;
- тесты: 22 в `tests/test_entities.py`, один `xfail(strict=True)` — заявка на
  вклад неоднозначного основания (`T-58b`).

**Замер:** набор из 60 пар — **25 честных из 30** (было 29), подмен 0, полоса
0,156 < 0,17 ≤ 0,25; пять сохранённых журналов — вердикты не изменились
(`reports/replay/2026-11-09-entity-readings.json`).

## Модель неверна — это признано

Разбор показал: **«МТС Беларусь» — не тёзка, а часть той же компании.** В
материале прямо: «услуги в России и Беларуси под торговой маркой „МТС“ …
обслужила 87,6 млн, в России — 81,9 млн, в Беларуси — 5,7 млн». То есть
81,9 + 5,7 = 87,6 — одна организация, разные **области**.

Отсюда ошибки:

| Что сделано | Почему неверно |
|---|---|
| прочтения как **непересекающиеся** идентичности | иерархия — не разбиение: `МТС Беларусь` ⊂ `МТС` |
| `entity-mismatch` для «МТС в России» ↔ «МТС Беларусь» | организация одна, различается **область** |
| страна = идентичность | «российская компания» ≠ «числа только по России» |
| `claim_narrowed` («назвал страну — поверим») | локальное допущение вместо признака |
| «называй страну» в промптах | подгонка под одну аббревиатуру (откатано) |
| демоции `p-007`, `p-015`, `p-041`, `p-053` | строки про **ту же** компанию; честные подтверждения сняты по ложной причине |

Цена оставлена осознанно и названа: **25 из 30** вместо 29.

## Верная модель (чтобы не изобретать заново)

1. **Отношения — первоклассные данные:** `knowledge/entities/relations.yaml`
   (`subject`, `relation: same | part-of | other`, `object`, `quote`, `source`),
   статусы `proposed → approved`; отношение без цитаты не действует.
2. **Область** (`группа / страна / сегмент / рынок`) читается из слов самого
   текста: «консолидированная», «в России», «с учётом зарубежных рынков».
3. **Правило «часть не подтверждает целое»** — отдельно от «другая сущность»:
   `5,7 млн` «МТС Беларусь» не подтверждает «у МТС 5,7 млн».
4. **Veto, а не голос в сумме:** `other` или несовместимая область блокируют
   подтверждение независимо от скора (hard veto / two-stage).
5. **`support` + `evidence`:** «неизвестно» не противоречит и не подтверждает;
   голое имя даёт высокий `support` и низкий `evidence` → «не доказано».
6. **Три стадии:** извлечение (verbatim) → разрешение (к какой записи) →
   обогащение (только для нового).
7. **Провенанс и `sameAs` — поддерживающие, не решающие.**
8. **Анти-overfit гейт:** ни одного имени сущности в `src/` и `prompts/`
   (сегодня: 70+ вхождений в `src/`, 2 в примере промпта — см. `T-67`).

## Как проверить известную границу

```bash
uv run python -c "from pf.ground import verify_claim; \
print(verify_claim('оператор: МТС Беларусь, показатель: абонентская база, значение: 5.7, период: 2026', \
'У МТС 5,7 млн абонентов', 'проект/строка', 0).status)"
```

Ожидается `needs_review` (не `confirmed`). Если вернётся `confirmed` — правка
потеряна, и это видно одной командой, а не по памяти.

## Почему отложено

- Продукт делается для МегаФона: мультибрендовая группа в двух странах — не
  его сценарий.
- Цена верной модели — граф отношений с подтверждением цитатами, veto, перезамер
  всех порогов — недели, и она не покрывается выгодой.
- Разблокирует: запрос на групповую/мультибрендовую аналитику, либо второй
  демо-проект, где иерархия сущностей встречается (`T-68`).

## Рассмотрено и не сделано

Убрать провенанс из отрезка идентичности (вернуло бы `p-015`, `p-041`, `p-053`,
итого 28 из 30) — это ещё одна смена поведения до пересмотра модели. Первый шаг
при возобновлении: он не меняет модель, но снимает ложные демоции.
