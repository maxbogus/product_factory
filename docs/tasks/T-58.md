# T-58 — прочтения аббревиатуры: пересечение как число, «требует проверки» со ссылкой

**Фаза:** 1 · **SP:** 2 · **RICE:** 4.2 · **Статус:** ✅

**Доказательство:** `tests/test_entities.py` (критерий — весь файл: 22 теста,
из них один `xfail(strict=True)` — заявка на `T-58b`)

**Критерий приёмки** — `uv run pytest tests/test_entities.py -q`

## Проблема

«МТС» — не одна сущность с вариантами написания, а пучок прочтений: российский
оператор, белорусский, туркменский, сербский, украинский, банк, самолёт, система
единиц «метр-тонна-секунда», машинно-тракторная станция. Проверка сравнивала имя
**подстрокой**, поэтому строка «оператор: МТС Беларусь» подтверждала утверждение
про «МТС»: `support = 1.000`, `confirmed` (измерено на `project/data/telecom_open_metrics.csv`).

Причины были три: `_mentions` искал «МТС» подстрокой («мтс» входит в «мтс
беларусь»); составное «МТС Беларусь» не распознавалось как субъект вовсе
(части сверялись по леммам, а мешок слов короче четырёх букв не видит); поле
«регион» сверяло регионы, только когда регион назван **в утверждении**, — голое
«МТС» проходило с полем 1,0.

## Что сделано

1. **Прочтения — данные, а не код.** `knowledge/raw/2026-11-09/wikipedia_mts_meanings.txt`
   + запись в `manifest.jsonl` (`url`, `retrieved`, `kind: meanings`, `title`,
   `sha256`, `bytes`, note: текст предоставлен пользователем, CC BY-SA 4.0).
   `pf.meanings` разбирает перечень после фразы «может означать» и читает страну
   прочтения из названия и описания (описание — только там, где в названии есть
   аббревиатура: «российская учебная дисциплина» — про предмет, а не про страну).
   Список прочтений в коде не правится: новая аббревиатура — новый снимок.
2. **Тождество — число, а не вердикт.** `pf.entities.readings` даёт набор
   прочтений отрезка (строка таблицы — целиком, проза — по предложению), сужая
   по названию прочтения и по стране. `identity` сравнивает с прочтениями
   утверждения: `доля = |пересечение| / |прочтения утверждения|`.
3. **Три исхода.** Ноль пересечений — `entity-mismatch` (отказ); названное
   утверждением прочтение принято — тождество есть; не названо — `entity-ambiguous`
   с числом и ссылкой («совпало 1 из 21. Проверить: <снимок> (<url>)»).
4. **Потолок, а не подмена.** `pf.ground.field_verdict`: неоднозначность
   **понижает** подтверждение (`needs_review`) и не отменяет отказ — если степень
   низка из-за единиц, периода или величины, отказ остаётся отказом
   (`support_without_subject` это различает).
5. **Цитата больше не обходит проверку.** `_cap_by_readings` применяется и к
   дословной цитате: цитата из строки «МТС Беларусь» дословна и при этом не
   подтверждает утверждение про «МТС».
6. **Виды в таблице.** `entity-ambiguous` («прочтение не установлено»),
   `entity-mismatch` («в источнике другая сущность»), владелец — промпт: роли
   должны называть страну у неоднозначной аббревиатуры (`D-48`).

## Замер

**Набор из 60 пар** (поставляемый снимок, `D-39`): честных подтверждено 25 из 30
(было 29), подмен подтверждено 0 (было 0 при 2 «в пределах допуска»), полоса
порога 0,156 < 0,17 ≤ 0,25. Четыре пары перешли в «требует проверки»
(`p-007`, `p-015`, `p-041`, `p-053`): утверждение называет «МТС» без страны, а
источник называет прочтение. Это цена честности, а не регресс.

**Пять сохранённых журналов** (`make replay`, снимок
`reports/replay/2026-11-09-entity-readings.json`): вердикты не перевернулись —
ни один (подтверждено 64, нет данных 88, требует проверки 7). Причина названа:
там, где модель привела цитату, сверка идёт дословно (`D-38`), а прочтения
срабатывают на утверждениях без цитаты — ровно там, где была утечка. Пробы 8/8.

Снимок набора — `reports/replay/2026-11-09-entity-readings.json`; A/B «с
прочтениями и без» на тех же журналах даёт 0 различий.

## Чего задача не делает

- **Не снимает бинарность ворот.** `Support.is_usable` по-прежнему `status is
  CONFIRMED`: неоднозначное основание даёт ноль в выводе, хотя в отчёте
  называется. Это `T-58b` (вклад числом). Заявка закреплена тестом
  `test_entities_ambiguous_basis_contributes_more_than_zero` с
  `xfail(strict=True)`: появится вклад — тест покраснеет и потребует снять пометку.
- **Не решает за человека.** `T-58c`: `pf decide --subject "МТС" --reading "…"`
  сузит прочтения и даст «опирается на решение пользователя» (`D-49`), не
  `CONFIRMED`.
- **Не выводит прочтения из корпуса и не угадывает их.** Заголовки корпуса дают
  6 названий для «МТС» и ни одного для «Tele2», «Билайн», «МГТС» — поэтому
  источник прочтений один: снимок страницы значений. Нет снимка — «проверить
  нечем», и проверка ведёт себя как раньше (названо в отчёте).
- **Не обновляет снимок сам.** Детерминизм важнее свежести; замена снимка —
  отдельное действие с новой записью манифеста.
- **Не различает прочтения по провенансу материала** отдельным признаком: URL
  строки попадает в текст и сужает источник сам, но веса у этого признака нет —
  это ансамбль `T-58b`.
