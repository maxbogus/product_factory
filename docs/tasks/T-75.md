# T-75 — свип модели и окна по ярусам

**Фаза:** 2 · **SP:** 3 · **RICE:** 4.5 · **Статус:** ⬜

**Критерий приёмки** — `uv run pytest tests/test_role_sweep.py -k sweep_decision -q`

## Проблема

Модель по ролям (`PF_ROLE_MODEL_*`) включена, но выбор сделан по одному
прогону: 12b держит схему, однако уходит на CPU (25 %) и оставляет пустые
`evidence`; 8b быстрее в 2,5×. Окно 12288 выбрано замером D-20, но после
подъёма лимита до 4096 его стоит перепроверить.

## Что сделать

1. Матрица «ярус × модель» на демо-вопросе, ≥3 прогона на клетку (дисперсия
   локальных моделей велика).
2. Метрики клетки: проход схемы (с ретраями T-74), доля подтверждённых и
   фантомов, время, `ollama ps` (GPU/CPU), обрезка промпта.
3. Окно перепроверить по `prompt_eval_count` журнала; ожидание — 12288.
4. Заморозить выбор в `docs/decisions.md` (D-6x) и в `PF_ROLE_MODEL_*`.

## Чего задача не делает

- Не добавляет окно на роль: окно остаётся глобальным (иное — отдельная
  задача, и размер промпта не ложится на ярусы).
