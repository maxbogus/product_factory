# T-12 — пересмотр выводов при новых данных

**Фаза:** 4 · **SP:** 3 · **RICE:** 4.8 · **Статус:** ⬜

## Проблема

Бриф, дополнительный уровень: «Пересмотр при новых данных. Агент находит,
какие выводы затронуты новыми сведениями, и обновляет их». В описании
честно стоит «нет», а в README нарисован цикл «обязательства → новые
данные» — то есть обещание есть, механизма нет.

Инфраструктура готова: `knowledge/raw/<дата>/manifest.jsonl` хранит
`sha256` каждой выгрузки, `knowledge_store.sha256_file` умеет считать хеш
заново. Не хватает команды, которая сравнивает и говорит, что затронуто.

## Что сделать

1. `pf review --session <id>`: для каждой выгрузки, на которую опирался
   вывод, сравнить хеш в манифесте с текущим файлом.
2. Если хеш изменился — перечислить, какие основания и обязательства
   ссылались на эту выгрузку, и поставить им пометку «требует пересмотра».
   Ничего не переписывать: журнал append-only, пересмотр — отдельный
   результат, а не правка истории.
3. Отчёт: раздел «Что затронуто новыми данными».
4. Eval-кейс `D-26-review-on-changed-data` и сценарий `R-01`/`R-02`.
5. README: цикл либо работает, либо убран — сейчас он нарисован, а
   механики нет (это и есть задача T-05).

**Критерий приёмки** — `uv run pytest tests/test_review.py -q`

## Заметки

- Сравнение хешей — не «обновление данных»: агент не скачивает заново, он
  отвечает на вопрос «устарел ли вывод».
- Хеш меняется и при косметической правке файла. Поэтому вывод — «требует
  пересмотра», а не «вывод неверен». Это ровно тот случай, когда честная
  формулировка важнее красивой.
- Прежний ответ агента не становится фактом: пересмотр — это новый шаг с
  новым основанием (правило из брифа про память между сеансами).
- Зависит от T-09: пока `knowledge/raw` не в контексте, опираться на
  выгрузку вывод не может.
