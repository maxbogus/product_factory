# T-10 — покрытие сценариев

**Фаза:** 2 · **SP:** 3 · **RICE:** 4.0 · **Статус:** ⬜

## Проблема

Сценарный слой есть, но описывает только позитивную ветку проверки
оснований: `tests/features/grounding.feature`, 12 сценариев. Требования
брифа про рабочий процесс, источники и стратегию держатся обычными
unit-тестами, которые человеку ничего не обещают, — а гейт
`every-scenario-has-test` проверяет лишь те feature-файлы, которые уже
лежат.

То есть «покрыто» сейчас означает «есть тесты», а не «поведение описано и
исполняется».

## Что сделать

Добавить четыре feature-файла (шаги — в `tests/test_scenarios.py`, гейт
потребует определение на каждый шаг):

1. `workflow.feature` — сквозной путь, вопрос человеку и его ответ,
   остановка и продолжение, исчерпанный бюджет, маршрут назад, сбой модели,
   шаг без источников (`W-01`…`W-08`).
2. `sources.feature` — абзац материала, строка таблицы, документы
   PDF/DOCX/XLSX, внешний источник «требует проверки», `robots.txt`,
   релевантность, снимок из `knowledge/raw` (`S-01`…`S-07`).
3. `strategy.feature` — три варианта с полюсами, возражения, нарушенное
   ограничение, чужой бренд в сообщении, полный план проверки,
   согласованность частей (`T-01`…`T-06`).
4. `data.feature` — метрика по строке, ряд не складывается, пересчёт не
   сходится, формула обязательна (`D-21`…`D-24`).

Плюс новые eval-кейсы: `D-21` (ограничение), `D-22` (вердикт гипотезы),
`D-23` (полюса вариантов), `D-24` (пересчёт метрики не сходится),
`D-25` (уникальные источники вывода).

**Критерий приёмки** — `uv run pytest tests/test_scenario_coverage.py -q`

## Заметки

- После `T-02` полюса вариантов проверяет схема, и это показывают кейсы
  `D-05`/`D-06`. Отдельный кейс `D-23` («полюса вариантов») заводить только
  если он проверяет **новое**: например, набор, где полюс объявлен маркером, а
  варианта с таким названием нет, — иначе получится дубль.
- Каждый сценарий обязан иметь определение шага: гейт `every-scenario-has-test`
  ловит именно ту ошибку, что была в прогоне (шаг переименовали, определение
  осталось).
- Числа BDD-сценариев в `docs/canon.py` (`SCENARIOS_BDD`) и кейсов
  (`EVAL_CASES`) обновляются вместе с файлами — иначе `make canon` покраснеет.
- Зависит от T-02: сценарий T-01 «полюса вариантов» осмыслен только когда
  схема их действительно требует.
