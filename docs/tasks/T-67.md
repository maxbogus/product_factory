# T-67 — имена субъектов и доменные термины: данные, а не код

**Фаза:** 1 · **SP:** 3 · **RICE:** 9.0 · **Статус:** ✅

**Доказательство:** `tests/test_no_entity_names.py` (критерий — `-k entity_names`:
литералы — `-k entity_names_absent_from_code`, докстринги — `-k absent_from_docstrings`,
промпты — `-k in_prompts_only_as_example`, переносимость —
`-k second_domain_needs_no_code_change`, отказ при отсутствии словаря —
`-k dictionary_is_required`)

**Критерий приёмки** — `uv run pytest tests/test_no_entity_names.py -k entity_names -q`

## Проблема

Доменный словарь живёт в логике, и это уже мешает двум вещам сразу:

```
src/pf/canonical.py    21 вхождение брендов (SUBJECTS: МТС, МТС Беларусь, МегаФон, Tele2,
                       ВымпелКом, Билайн, Ростелеком, Yota)
src/pf/lexical.py      10   (примеры и правила терминов)
src/pf/corpus.py        5   (DOMAIN_TERMS, STRONG_DOMAIN_TERMS)
src/pf/sources.py       3
src/pf/ground.py        3
src/pf/workflow.py      2
src/pf/entities.py     10   (докстринги с примером «МТС Беларусь» — уйдут с T-58)
prompts/roles/collector.md  2 (пример JSON, не правило)
```

Последствия: (1) анти-overfit гейт «ни одного имени сущности в `src/`» **сегодня
падает**; (2) второй демо-проект на другом домене (`T-68`) невозможен — проверка
знает телеком-бренды из кода; (3) пополнение домена — правка `src/`, а не данных.

## Что сделать

1. `knowledge/domain/entities.yaml` — субъекты (каноническое имя + алиасы +
   страна/область, если известна) и термины домена; формат как у
   `knowledge/lexicon/synonyms.yaml` (version, metadata, записи).
2. `corpus.DOMAIN_TERMS` / `STRONG_DOMAIN_TERMS` и `canonical.SUBJECTS` читаются
   из этого файла; в коде остаются только структуры и правила, без имён.
3. Кэш по mtime, как у словаря лексикона: пополнение действует сразу.
4. Гейт `tests/test_no_entity_names.py`:
   - падает, если имя из `entities.yaml` встречается в `src/pf/*.py` **вне
     докстрингов-примеров** (проверка по строковым литералам, не по комментариям);
   - падает, если имя встречается в `prompts/roles/*.md` как правило (пример
     JSON допускается и помечается словом «пример»);
   - держит обратное: тест с новым доменом (`биология`) проходит без правки `src/`.
5. Докстринги с примерами переписать нейтрально («Оператор А», «компания А»).

## Что сделано

1. `knowledge/domain/entities.yaml` (+ `README.md`): 10 субъектов (вид, написания,
   страна, «наш бренд», «конкурент»), 39 записей терминов с тремя признаками,
   шаблоны заголовков, основы отбора выдачи, сайты брендов. Содержимое снято
   **из прежнего кода скриптом**, а не переписано руками: перенос не добавил и не
   потерял ни одного термина (23 сильных, 17 чистых, 34 доменных).
2. `src/pf/domain.py`: разбор файла, `DomainError` при отсутствии/порче, кэш по
   `(путь, mtime)`, шаблоны собираются из данных (длинные слова первыми),
   `subjects`, `ours`, `competitors`, `subject_groups`, `strong/clean/domain_terms`,
   `search_stems`, `web_domains`, `summary` для `pf doctor`.
3. Переключены потребители без смены поведения: `canonical.SUBJECTS` → функция,
   `corpus` (три набора + два шаблона), `schemas.COMPETITOR_BRANDS` → функция,
   `web` (основы отбора, домены брендов), `synonyms` (пары написаний приходят из
   домена через `lexicon.groups`), 6 фикстур `evalrun` берут имена из домена.
4. Докстринги обезличены: «Оператор А», «компания А», «дочерняя компания». Имена
   в комментариях оставлены: комментарий — пояснение для человека, и это
   легальное место для примера (гейт читает литералы).
5. Гейт `tests/test_no_entity_names.py` — 5 проверок: литералы, докстринги,
   промпты (только раздел «Пример»), второй домен без правки кода, обязательность
   словаря.
6. `pf doctor` печатает «Домен: N субъектов, M терминов — путь (имя домена)» и
   падает, если словарь не читается.

**Отступления от плана — названы.**

- Критерий приёмки был `-k no_names_in_code`, стал `-k entity_names`: старый ключ
  выбирал бы одну проверку из пяти, а критерий обязан выбирать все тесты задачи
  (`AGENTS.md`).
- `web._STRONG_TERMS` и `web.TELECOM_CATEGORIES` **удалены**: их никто не читал.
  Переносить мёртвый список в данные значило бы объявить фильтр, которого нет.
  Поэтому `search.strong_terms` в файле домена тоже нет — только `strong_stems`.
- Сайты брендов (`megafon.ru`, `mts.ru`, `beeline.ru`) ушли из
  `Settings.allowed_domains` в домен и складываются с настройками в
  `pf.web.allowed_domains`: политика выборки и свойство домена — разные вещи.

**Доказательство, что поведение не изменилось.** `make replay` до и после:
`подтверждено 64 → 64`, `нет данных 88 → 88`, `опора на ввод пользователя 5 → 5`,
`требует проверки 2 → 2`, `величин-фактов без расчёта 1 → 1`, перевёрнутых
вердиктов **0**, контрольные пробы **8 из 8**. Шаблоны заголовков сверены на 14
контрольных названиях — совпадение с прежними регулярками во всех случаях.

## Чего задача не делает

- Не решает тождество сущностей: модель отложена (`T-58`), здесь только перенос
  словаря из кода в данные.
- Не трогает `data/wiki` и корпус: это источники, а не словарь домена.

## Границы

- Гейт проверяет литералы, а не смысл: правило «не пиши имя в коде» остаётся
  соглашением, которое ловит типичный случай.
- Домен из `knowledge/domain/` — данные проекта; для второго проекта он другой,
  и это ровно то, что делает `T-68` проверяемым.
