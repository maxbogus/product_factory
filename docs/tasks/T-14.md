# T-14 — `expected` участвует в вердикте eval

**Фаза:** 1 · **SP:** 3 · **RICE:** 2.7 · **Статус:** ⬜

## Проблема

В `eval/cases/scenarios.jsonl` у каждого кейса есть колонка `expected`
(`PASS` / `REJECT` / `RECHECK`) — она описывает исход, который агент обязан
показать. Раннер её разбирает (`src/pf/evalrun.py:86`), но **не
использует**: `_run_case` (`:145-162`) проверяет только `must_contain` и
`must_not_contain`. Значит «Пройдено 20 из 20» держится на подстроках, а не
на заявленной классификации: кейс, помеченный `REJECT`, спокойно проходит,
если обработчик вернул нужное слово.

Это тот же класс ошибки, что `D-05`/`D-06` (см. `T-02`): проверка
существует, а проверить ею нечего.

## Что сделать

1. `Result` получает поле исхода: обработчик возвращает не строку, а пару
   «исход + текст» (`Expectation` + `str`). Текст остаётся человеческим.
2. `_run_case` сверяет заявленный `expected` с фактическим исходом и
   отдельно — подстроки. Расхождение исхода и подстроки — два разных
   сообщения, чтобы было видно, что именно разошлось.
3. Все 20 обработчиков сообщают исход: отказ схемы — `REJECT`, ответ,
   которому не хватает обязательной части, — `RECHECK`, годный ответ —
   `PASS`.
4. Красный прогон обязателен: кейс с подменённым `expected` (например,
   `D-02` помечен `PASS`) должен покраснеть. Сегодня он зелёный.
5. `docs/TASKS.md` § 5: убрать из «что осознанно не делается», если
   запись там появится.

**Критерий приёмки** — `uv run pytest tests/test_eval_cases.py -k expectation -q`

## Заметки

- Зависит от `T-02`: он тоже правит обработчики `D-05`/`D-06` и тексты
  кейсов. Делать в обратном порядке — конфликт в одном файле.
- `T-02` уже исправил `expected` у `D-05`/`D-06` с `RECHECK` на `REJECT`:
  обработчики показывают отказ схемы, а не ответ с нехваткой части. Остальные
  обработчики при включении колонки нужно разметить заново — по фактическому
  исходу, а не по прежней догадке.
- `expected` — не косметика: без него набор заявляет классификацию
  требований брифа и не отвечает за неё.
- Оценка низкая намеренно: набор уже исполнимым был (`T-01`), это
  следующий слой — сделать исполнимым **заявленный исход**.
