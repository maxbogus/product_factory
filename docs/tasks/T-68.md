# T-68 — второй демо-проект: переносимость доказана, а не обещана

**Фаза:** 3 · **SP:** 3 · **RICE:** 8.0 · **Статус:** ⬜ · **Зависит от:** T-67

**Критерий приёмки** — `uv run pytest tests/test_portability.py -k second_project -q`

## Проблема

Демонстрация одна и та же: телеком, удержание, абонентская база. Жюри проверяет
критерий «справляется с новыми задачами», а доказательства переносимости нет:
домен зашит в код (`T-67`), материалов второго проекта нет, прогон не показан.

Без второго проекта любая заявка «агент переносим» — обещание, а не факт. И
именно на этом ловятся работы, где всё настроено под одну задачу.

## Что сделать

1. `project2/` — материалы второго проекта из **другого домена**. Корпус уже
   содержит разделы `biology`, `economics`, `mathematics` (`data/wiki`), поэтому
   скачивать ничего не нужно: берём вопрос вне телекома (например, продукт про
   профилактику/диагностику — по материалам корпуса).
2. Домен для второго проекта — `knowledge/domain/entities.yaml` второго проекта
   (или отдельный файл, если домен переопределяется): гейт `T-67` обязан пройти
   без правки `src/`.
3. Прогон: `pf run` на втором проекте (живой или на сохранённых ответах ролей),
   документ `project2/RESULT.md` собирается тем же `pf.artifacts.build_document`.
4. Тест `tests/test_portability.py`:
   - второй проект читается материалами (`scan_materials`), основания
     проверяются, отчёт строится;
   - в коде **ноль** правок: тест сравнивает список изменённых файлов `src/`
     с пустым (через `git diff --name-only` в тесте — только если дерево git);
   - известный провал фиксируется: на материале без цифр проверка говорит «нет
     данных», а не подтверждает.
5. В `docs/DESCRIPTION.md` — раздел «переносимость»: два проекта, что общего в
   механике, что задаётся данными.

## Чего задача не делает

- Не доказывает качество стратегии на втором домене: это проверка механики
  (материалы → основания → варианты → стратегия → план), а не экспертиза.
- Не добавляет данные: только то, что уже лежит в корпусе.

## Границы

- Второй прогон может быть на сохранённых ответах ролей: живой прогон дорог и
  зависит от модели. Тогда в документе это названо.
- Домен второго проекта узкий: он проверяет переносимость механики, а не
  универсальность словаря.
