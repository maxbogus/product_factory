# T-85 — экспертный тематический справочник (`domain-reference`)

**Фаза:** 4 · **SP:** 5 · **RICE:** 1.2 · **Статус:** ✅

**Критерий приёмки** — `uv run pytest tests/test_domain_reference.py -q`

## Проблема

Правило `domain-reference` в `architecture/rules/fitness-rules.yaml` — `planned`:
блока «СПРАВОЧНИК» в контексте нет, проверять нечего. Агенту не хватает
экспертного слоя понятий домена рядом с материалами.

## Что сделать

1. Справочник как данные (`knowledge/domain/reference.yaml` или `knowledge/raw`).
2. Блок «СПРАВОЧНИК» в контексте, отдельный от оснований: справочное знание не
   подтверждает факт (статус «требует проверки», не `CONFIRMED`).
3. Перевести правило в `implemented` вместе с тестом.

## Результат

- **Справочник как данные:** `knowledge/domain/reference.yaml` — понятия
  eSIM, MVNO, ARPU, ключевая ставка; у каждого «что это», «когда применимо»,
  «когда неприменимо».
- **Модуль** `src/pf/reference.py`: загрузка с кэшем по пути и времени
  изменения файла, `as_lines()` для блока, `source_id_of` / `is_reference` /
  `text_of` для проверки цитаты. Нет файла — пустой блок, а не ошибка
  (второй проект может обойтись без справочника).
- **Блок «СПРАВОЧНИК»** идёт в контекст `analyst`, `options`, `redteam`,
  `strategy`, `keeper` отдельно от материалов и внешних источников; помечен
  «не факт о кейсе; статус: требует проверки».
- **Цитата из справочника** проверяется на дословность, но статус не выше
  «требует проверки» (`mark_external`), вид отказа `reference`; выдуманная
  цитата — отказ, а не «ждёт человека».
- **Правило включено:** `domain-reference-is-not-case-fact` → `active`,
  `implementation-status: domain-reference` → `implemented` (модуль + тест).
  `make contracts-check`: 9 правил, нарушений нет.

**Доказательство:** `tests/test_domain_reference.py` (5 проверок: данные,
отметка блока, «требует проверки» для дословной цитаты, отказ для выдумки,
активность правила и реализации).
