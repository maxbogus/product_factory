# T-50 — обязательство по шаблону: база, метод, контрольная группа, откат

**Фаза:** 2 · **SP:** 3 · **RICE:** 7.0 · **Статус:** ✅

**Доказательство:** `tests/test_commitments.py` (критерий — `-k template`: 5 проверок: поля схемы и старый журнал, таблица и счётчик «без базы», замечания, сверка числа в базе).

## Проблема

`schemas.Commitment` знает четыре поля: формулировку, владельца, показатель и
условие пересмотра. Этого мало, чтобы обязательство можно было **проверить**:

- нет **базовой линии** — «удержание вырастет на 5 %» не говорит, от чего;
- нет **метода измерения** — «доля уведомлений до списания» считается по
  доставке, по открытию или по факту оплаты;
- нет **контрольной группы** — в `cloud-deepseek-2` это есть в плане проверки, но
  не в обязательстве: исполнитель не знает, с чем сравнивать;
- нет **условия отката** отдельно от условия пересмотра: «пересмотреть» и
  «откатить» — разные действия.

## Что сделать

1. `schemas.Commitment`: `baseline`, `measurement`, `control_group`, `rollback` —
   пустые по умолчанию, старые журналы читаются без миграции.
2. `prompts/roles/keeper.md`: каждый пункт с примером «плохо / хорошо», как уже
   сделано для условия пересмотра.
3. `report.conclusion_markdown`: полная таблица обязательства (или вторая строка
   под таблицей) плюс счётчик «без базы: N из M» — по образцу «Без владельца» из
   `T-52`.
4. `Workflow._plan_number_texts`: новые поля попадают в сверку чисел (`T-17`):
   число в базовой линии — тоже утверждение и тоже требует расчёта.
5. Замечания «обязательство без базы / без метода» — в `rejected_details` фазы
   решения, без остановки прогона.

## Что сделано

1. `schemas.Commitment` получил `baseline`, `measurement`, `control_group`,
   `rollback` — пустые по умолчанию; унаследованный журнал читается без
   миграции (`model_validate` без полей не падает).
2. `report.conclusion_markdown` — таблица обязательства с новыми колонками
   (База, Метод, Контрольная группа, Откат) и счётчик «Без базы: N из M» по
   образцу «Без владельца». Унаследованный журнал не судится: если ни одно
   обязательство ключа `baseline` не несёт, счётчика нет — сравнивать нечем,
   а не «всё заполнено».
3. `Workflow._plan_number_texts` — новые поля в сверке чисел: `baseline` как
   **факт** (число в базе — утверждение о мире, понижает статус при отсутствии
   расчёта), `measurement` / `control_group` / `rollback` как **цель** (порог,
   а не измерение, — статус не понижает, `D-47`).
4. `Workflow._check_commitment_template` — замечания «без базы» и «без метода»
   уходят в `rejected_details` фазы решения новым видом
   `commitment-template` (`verdicts.KINDS`), без остановки прогона.
5. `prompts/roles/keeper.md` — у каждого пункта шаблона пример «плохо / хорошо»;
   формат ответа и правило чисел называют базу.

**Доказательство поведения.** `demo/RESULT.md` пересобран из журнала
`demo-v12` (`make demo-doc SESSION=demo-v12`): изменилась только шапка таблицы
обязательства и строки заполнения — счётчика «Без базы» нет, потому что старый
журнал поля не записывал. `test_document_matches_its_journal` зелёный.

## Чего задача не делает

- не делает поля обязательными в схеме: прогон без базы должен остаться
  возможным, но названным;
- не заменяет `T-51`: допущения вывода и шаблон обязательства — разные блоки.

**Критерий приёмки** — `uv run pytest tests/test_commitments.py -k template -q`
