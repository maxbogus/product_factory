# T-58b — вес основания вместо `is_usable`: вклад, а не ноль

**Фаза:** 1 · **SP:** 3 · **RICE:** 3.5 · **Статус:** ⬜ · **Зависит от:** T-58

**Критерий приёмки** — `uv run pytest tests/test_ground.py -k contribution -q`

## Проблема

Три состояния есть в отчёте, но не в решении. Ворота — булево:

```python
@property
def is_usable(self) -> bool:
    """Можно ли опереться на это основание."""
    return self.status is SupportStatus.CONFIRMED
```

`NEEDS_REVIEW` в решении равен нулю, и любая трёхзначная логика выше ворот
схлопывается при первом же неоднозначном «МТС». Подтверждение со степенью 1,0 и
0,25 неразличимы: оба `is_usable = True`. `GroundTally` считает четыре `int`,
`conclusion_status` возвращает строку — доля не едет в вывод.

Заявка закреплена в `T-58`: `tests/test_entities.py::test_entities_ambiguous_basis_contributes_more_than_zero`
помечен `xfail(strict=True)` и ждёт вклада.

## Что сделать

1. **`Support.support: float` и `Support.share: float`** — число едет в основание
   вместе со статусом.
2. **`Support.contribution`** — функция, а не флаг: `CONFIRMED → support · share`;
   `NEEDS_REVIEW → support · share · AMBIGUOUS_FACTOR` (именованная константа,
   замороженная замером); `NO_DATA → 0.0`. `is_usable` остаётся производным
   (`contribution == 1.0`) и документируется, чтобы не изменить смысл молча.
3. **`sources.py` выбирает кандидата по максимуму `contribution`**, а не «первый
   подходящий» (сейчас — `if result.is_usable: return result`).
4. **`GroundTally`** → `weight: float`, `ambiguous_weight: float`,
   `parts: dict[str, float]`; целые счётчики остаются для отчёта (журналы
   append-only, у старых записей веса нет — «записано прогоном»).
5. **`conclusion_status` → `ConclusionSupport {label, support: float, parts}**;
   `__str__` возвращает ярлык, поэтому отчёт и документ читаются как раньше, но
   **решение принимается по числу**, а ярлык — производная от полос.
6. **Перезамер**: `make tune-conclusion` (полосы ярлыка и `AMBIGUOUS_FACTOR`),
   `make replay` со снимком, `docs/canon.py` и четыре документа с числами,
   `tests/test_conclusion_grounding.py` (список частей правила),
   `CONCLUSION_RULE_PARTS += ("weighted-grounds",)`.

## Чего задача не делает

- Не поднимает статус: `contribution ≤ 1` по построению, `mark_external` и
  правила выгрузок не ослабляются.
- Не переписывает журналы: у старых записей числа нет, и это называется словами.
- Не решает за человека: решение о прочтении — `T-58c`, и оно даёт
  «опирается на решение пользователя», а не `CONFIRMED` (`D-49`).

## Границы

- `AMBIGUOUS_FACTOR` и полосы ярлыка — числа из замера, а не вкус: тест
  `test_conclusion_bands_are_frozen_by_measurement` краснеет, если они поехали.
- Вес неоднозначного основания не делает вывод «подкреплённым»: он делает его
  **измеримо** слабее, и это видно в отчёте разбивкой.
