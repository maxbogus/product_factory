# T-07 — вердикт гипотез

**Фаза:** 2 · **SP:** 3 · **RICE:** 4.9 · **Статус:** ✅

## Проблема

Бриф требует «провести настоящее исследование, проверить гипотезы и дать
рекомендацию». Сейчас гипотезы только формулируются: `Analysis.hypotheses`
— список утверждений без источника, и всё. Ни вердикта, ни связи с
собранными основаниями, ни видимости в отчёте. В реестре реализации это
`hypothesis-verification: not_implemented`.

Читатель видит «гипотеза: отток из-за цены» и не может понять, проверяли её
или забыли.

## Что сделать

1. Схема: у гипотезы появляется `verdict` (`supported` / `refuted` /
   `unknown`) и `verdict_basis` — на чём он держится. Значение по умолчанию
   — `unknown`: гипотеза без проверки не считается подтверждённой.
2. Правило статуса — в коде, а не в промпте: `supported` требует хотя бы
   одного подтверждённого основания, `refuted` — основания, которое
   гипотезе противоречит (по показателю и полярности, как в
   `Workflow._find_contradictions`).
3. Отчёт (`pf report`) и документ демонстрации: строка «гипотезы:
   поддержано N, опровергнуто N, требует проверки N».
4. Eval-кейс `D-22-hypothesis-verdict`.
5. `architecture/rules/implementation-status.yaml`: `hypothesis-verification`
   → `implemented` с модулем и тестом.

**Критерий приёмки** — `uv run pytest tests/test_hypotheses.py -k verdict -q`

## Заметки

- Гипотеза без источника не становится фактом ни при каком вердикте: это
  отдельный класс утверждений (`Claim.kind == "гипотеза"`).
- `unknown` — это результат, а не провал: так же, как объявленный пробел.
- Связано с T-08: вердикт `unknown` — вход для добора оснований.

## Что сделано

- `src/pf/hypotheses.py`: `Verdict` (`supported` / `refuted` / `unknown`),
  `HypothesisVerdict` (`verdict`, `basis`) и `verdict_of(hypothesis, grounds)`.
  Правило: совпадение предмета — поддержано, противоположное направление —
  опровергнуто, иначе неизвестно; гипотеза без направления не опровергается
  ни ростом, ни падением показателя.
- `src/pf/lexical.py`: `polarity`, `topic_words` и списки слов о направлении —
  одно правило на репозиторий. `Workflow._polarity` / `_topic_words` делегируют
  туда же, поэтому противоречия в фактах и вердикт гипотез считают направление
  одинаково.
- `src/pf/schemas.py`: `Claim.verdict` и `Claim.verdict_basis`, по умолчанию
  `unknown`; валидатор `_drop_model_verdict` отбрасывает значение из ответа
  модели — вердикт ставит код.
- `src/pf/workflow.py`: `_confirmed_grounds` (только `CONFIRMED`) и
  `_apply_hypothesis_verdicts`, вызов — в фазе `ANALYZING` до сериализации шага,
  поэтому вердикт попадает в журнал вместе с разбором.
- `src/pf/report.py`: `_collect_hypotheses` (последний разбор, старый журнал
  считается `unknown`), поле `hypotheses` в отчёте и в `report_as_dict`, строка
  «поддержано N, опровергнуто N, требует проверки N».
- Eval-кейс `D-22-hypothesis-verdict`; регресс
  `tests/test_eval_cases.py::test_case_d22_goes_red_without_verdict_rule` держит,
  что кейс падает при выключенном правиле.
- Реестр: `hypothesis-verification` → `partial` (вердикт есть, целевого
  добирания оснований нет — это `T-08`). Решение — `docs/decisions.md`, D-30.

**Доказательство:** `tests/test_hypotheses.py` (7 тестов, `-k verdict`) и
`tests/test_eval_cases.py` (регресс кейса `D-22`).

## Что осталось

- Целевое добирание оснований по гипотезам с вердиктом `unknown` — `T-08`.
- Гипотеза без подтверждённого основания остаётся `unknown` и в демо-прогоне:
  в материалах нет измерения удержания (`T-11`).
