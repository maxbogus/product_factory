# T-07 — вердикт гипотез

**Фаза:** 2 · **SP:** 3 · **RICE:** 4.9 · **Статус:** ⬜

## Проблема

Бриф требует «провести настоящее исследование, проверить гипотезы и дать
рекомендацию». Сейчас гипотезы только формулируются: `Analysis.hypotheses`
— список утверждений без источника, и всё. Ни вердикта, ни связи с
собранными основаниями, ни видимости в отчёте. В реестре реализации это
`hypothesis-verification: not_implemented`.

Читатель видит «гипотеза: отток из-за цены» и не может понять, проверяли её
или забыли.

## Что сделать

1. Схема: у гипотезы появляется `verdict` (`supported` / `refuted` /
   `unknown`) и `verdict_basis` — на чём он держится. Значение по умолчанию
   — `unknown`: гипотеза без проверки не считается подтверждённой.
2. Правило статуса — в коде, а не в промпте: `supported` требует хотя бы
   одного подтверждённого основания, `refuted` — основания, которое
   гипотезе противоречит (по показателю и полярности, как в
   `Workflow._find_contradictions`).
3. Отчёт (`pf report`) и документ демонстрации: строка «гипотезы:
   поддержано N, опровергнуто N, требует проверки N».
4. Eval-кейс `D-22-hypothesis-verdict`.
5. `architecture/rules/implementation-status.yaml`: `hypothesis-verification`
   → `implemented` с модулем и тестом.

**Критерий приёмки** — `uv run pytest tests/test_hypotheses.py -k verdict -q`

## Заметки

- Гипотеза без источника не становится фактом ни при каком вердикте: это
  отдельный класс утверждений (`Claim.kind == "гипотеза"`).
- `unknown` — это результат, а не провал: так же, как объявленный пробел.
- Связано с T-08: вердикт `unknown` — вход для добора оснований.
