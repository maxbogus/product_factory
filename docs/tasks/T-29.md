# T-29 — перевод в проверке и анализе: дословность в переводе, числа из оригинала

**Фаза:** 2 · **SP:** 3 · **RICE:** 3.0 · **Статус:** ⬜

## Проблема

Ветка «другой язык источника» (`src/pf/ground.py:700-727`) сегодня даёт
максимум «сверены только числа». Всё остальное — слова, точные термины,
отрицание — не проверяется, и цитата попадает в `needs_review` с одной и той
же строкой, из которой человек не узнаёт, была ли подмена термина.

## Что сделать

1. `ground.verify_quote(source_text, quote, source_id, *, source_ru="")`:
   в ветке «другой язык» сначала искать цитату дословно в `source_ru`.
   Числа — **всегда** из `source_text`.
   Статус остаётся `needs_review`, но `detail` различает:
   «дословно в переводе источника» / «сверены только числа».
2. `analysis.compute_from_rows`: материал с `translation_ok=False` в расчёт
   не идёт — число, потерянное переводом, не должно попасть в медиану.
3. `sources.indicator_of_citation` получает русское имя показателя из
   `text_ru`, чтобы `#rowN` не терял английский материал.
4. `report.py`: раздел «переводы» — цитата-перевод и оригинал рядом,
   с пометкой «перевод машинный, не основание».

## Чего задача не делает

- `SupportStatus` не расширяется: цитата из перевода **никогда** не становится
  `confirmed`;
- `mark_external` не ослабляется;
- перевод в контекст не подаётся — это `T-28` по флагу.

**Критерий приёмки** — `uv run pytest tests/test_ground.py -k translated_quote -q` и
`uv run pytest tests/test_analysis.py -k translated_numbers -q`

## Заметки

- Ошибка перевода может создать ложное основание. Поэтому числа сверяются с
  оригиналом, статус ограничен, а в отчёте видны оба текста.
- `_overlap_reason` начинает объяснять расхождение вместо «иностранный
  источник» — это и есть прирост «попаданий» без смягчения правила.
