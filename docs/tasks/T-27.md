# T-27 — перевод en→ru как слой: кэш, сохранность чисел, `pf translate`

**Фаза:** 2 · **SP:** 3 · **RICE:** 2.0 · **Статус:** ✅

## Проблема

Английский источник для агента сейчас почти бесполезен. `ground.verify_quote`
(`src/pf/ground.py:700-727`) для пары «английская цитата / английский источник»
имеет отдельную ветку: дословность недостижима, сверяются **только числа**,
статус — `needs_review` с пояснением «дословный перевод не проверяется».
Слова, термины, отрицание не проверяются вовсе: половина механизма честности
на английском материале просто не работает.

При этом ответы агента и вся схема — русские, а `grep` по
`prompts/roles/*.md` не находит **ни одного** упоминания языка ответа.

## Что сделать

1. `src/pf/translate.py`:
   - `Translation(text, engine, model, ok, notes, usage_tokens)` —
     `@dataclass(frozen=True, slots=True)`, как остальные типы проекта;
   - `numbers_of(text) -> Counter[str]` — числа, единицы (`%`, п.п., млн,
     руб.), идентификаторы (`#rowN`, `T-25`, `D-27`, `arXiv:1511.04023`,
     `econ.GN`, `§`);
   - `preserved(original, translated) -> tuple[bool, tuple[str, ...]]` —
     мультимножества обязаны совпасть, иначе перевод непригоден;
   - `translate(text, *, client=None, max_chars=1200) -> Translation` —
     режет по абзацам и границам предложений, промпт заморожен в модуле;
   - `TranslationStore` — кэш `knowledge/translations/<sha1[:16]>.yaml`
     (`source_sha1`, `engine`, `model`, `created_at`, `text_ru`, `numbers_ok`).
2. Модель недоступна (`LLMError`) → `Translation(ok=False)`, без исключения:
   деградация, а не отказ (как в `pf.web`).
3. `pf translate <файл|--text>` с `--json`; флаг `--refresh` — пересчитать кэш.
4. Строка языка в `Workflow._prompt_extras` (`src/pf/workflow.py:617-627`):
   «ответ по-русски, цитаты — дословно на языке источника» — третьим блоком.

## Чего задача не делает

- не меняет `SupportStatus` и `mark_external`: перевод не поднимает статус
  основания выше `needs_review`;
- не подаёт перевод в контекст модели — это `T-28` и только по флагу;
- не проверяет смысл перевода: проверяется сохранность чисел и
  идентификаторов, остальное — на человеке.

**Критерий приёмки** — `uv run pytest tests/test_translate.py -k numbers_preserved -q`

## Заметки

- Кэш обязателен: без него `make test` и `make replay` ходили бы в модель, а
  прогон перестал бы воспроизводиться.
- Формулы чисел берутся из `pf.lexical.numbers_in`/`numbers_match`, а не
  пишутся заново: правило числовой сверки в проекте одно.

## Доказательство

**Доказательство:** `src/pf/translate.py`, `tests/test_translate.py`, `src/pf/workflow.py`, `tests/test_prompts_language.py`

Красный прогон до работы: `uv run pytest tests/test_translate.py -k numbers_preserved -q`
давал `ImportError: cannot import name 'translate'` — модуля не было. После
реализации: 11 тестов зелёные, `make ci` — 537 passed, eval 20/20, contracts
8/8, canon и docs-check без расхождений.

Что именно держат тесты:

- `numbers_preserved_*` — потерянное и придуманное число одинаково блокируют
  перевод, а `87,5` и `87.5` считаются одним числом;
- `original_untouched_*` — оригинал не меняется, кэш ключуется оригиналом;
- `cache_hit_*` — второй перевод не тратит вызов модели;
- `model_down_*` — недоступная модель даёт `ok=False`, а не исключение;
- `all_roles_*` — языковой блок доходит до запроса, и ролей по-прежнему девять.
