# T-80 — обогатить материалы проекта под слабые вопросы

**Фаза:** 3 · **SP:** 3 · **RICE:** 3.5 · **Статус:** ✅

**Критерий приёмки** — `uv run pytest tests/test_demo_data.py -q`

## Проблема

Демо-вопросы про eSIM, MVNO, ценность тарифа и ключевую ставку упираются в
«неподкреплено»: корпус и `project/` не содержат ответа. Честность есть,
содержания для стратегии нет.

## Что сделать

1. Добавить открытые данные под q2/q3/q5: eSIM/MVNO (проникновение, ARPU),
   тарифы конкурентов, ключевая ставка — каждый файл с `url`, `retrieved`,
   `note`, `sha256`.
2. Ничего не выдумывать: число без источника не добавляется (D-31).
3. Проверить, что `pf materials` видит новые файлы и основания из них идут
   как «требует проверки» (D-29).

## Результат

- Добавлен `project/data/telecom_market_open.csv` — открытый ряд World Bank
  (`IT.CEL.SETS`, `IT.CEL.SETS.P2`): абоненты мобильной связи и проникновение
  (SIM на 100 человек) по России, 2014–2024. Метаданные: `url`, `retrieved`,
  `note`, `sha256`, `bytes` (`telecom_market_open.csv.meta.json`). Значения
  перенесены как отдал API, без пересчётов.
- `pf materials` видит файл (22 абзаца, `table`, материал проекта),
  `pf sources` ставит его в срез; из ряда считается изменение и
  подтверждается пересчётом (`verify_metric`).
- **Границы названы, а не замазаны.** Это размер рынка и проникновение
  мобильной связи, а **не** проникновение именно eSIM, **не** доля MVNO и
  **не** тарифы конкурентов: таких структурированных открытых данных нет
  (`D-31`). Подмена понятия не вводится.

**Доказательство:** `tests/test_demo_data.py` (`-k weak_question`); там же
расчёт проверяется `verify_metric`.
