# Сценарий видеозаписи работы агента (до 10 минут)

Бриф требует: «Видеозапись работы агента до 10 минут — обязательно.
Сквозной путь демонстрационного проекта: запрос, работа агента,
варианты, стратегия, продолжение после перерыва».

Видео снимается с экрана терминала, голос не нужен: комментарии
накладываются текстом. Порядок — ровно тот, в котором агент реально
работает.

---

## Тайминг

| Время | Экран | Что показываем | Что происходит |
|---|---|---|---|
| 0:00-0:40 | терминал | `make doctor` | Окружение готово: Python, Ollama, модель, корпус, промпты |
| 0:40-1:10 | терминал | `pf run "Почему падает удержание..."` | Запрос руководителя. Агент сам идёт по фазам |
| 1:10-3:00 | терминал | тот же экран | Работа агента: 9 фаз, видно основания и отклонения. Комментарий: «проверка оснований — не просьба модели, а код» |
| 3:00-4:10 | терминал | итог стратегии | Варианты (три, с возражениями), продуктовая и коммуникационная части, план проверки |
| 4:10-5:00 | терминал | `pf log` | Журнал: что подтверждено, что отклонено и почему, сколько токенов |
| 5:00-5:40 | терминал | `pf cost` | Расход по ролям: видно, какая роль дороже |
| 5:40-6:40 | терминал | `pf web "отток абонентов" --parse` | Поиск в интернете и разбор найденных страниц. Комментарий: «внешнее никогда не подтверждено — только требует проверки» |
| 6:40-7:20 | терминал | `pf stop` | Остановка работы на середине |
| 7:20-8:00 | терминал | `pf resume` | Продолжение с сохранённого места: та же фаза, те же данные |
| 8:00-9:00 | терминал | `pf eval` | 12 eval-сценариев: правила поведения агента проверяются |
| 9:00-9:40 | терминал | `pf bench` или отчёт | Цифры: агент против обычного чата |
| 9:40-10:00 | терминал | `pf mcp static-parser` | Инструменты MCP доступны из интерфейса |

---

## Что должно быть видно обязательно

1. **Запрос** — задача руководителя вводится целиком.
2. **Работа агента** — фазы идут сами, без вмешательства.
3. **Варианты** — минимум три, у каждого сильное возражение.
4. **Стратегия** — продуктовая, коммуникационная и план проверки.
5. **Продолжение после перерыва** — `pf stop`, затем `pf resume`.

## Комментарии, которые стоит наложить текстом

- «Факт без дословной цитаты отбрасывается. Это код, а не просьба модели.»
- «Агент называет пробелы: данных об оттоке в открытых источниках нет.»
- «Внешний источник проходит проверку, но его статус — требует проверки.»
- «Расход виден по ролям: видно, за что платишь.»
- «Работа продолжается с того же места — состояние лежит на диске.»

## Подготовка

```bash
make setup
ollama pull qwen3:8b
make doctor
# прогреть демо, чтобы на видео шло быстро:
uv run pf run "Почему падает удержание у мобильного тарифа и что с этим делать?"
# очистить журнал, чтобы в кадре были чистые цифры:
rm -f journal/session-demo*.jsonl state/session-demo*.json
```

Терминал: шрифт покрупнее, тёмная тема, окно на весь экран.

## Чего не делать

- Не запускать `make demo` вслепую: демонстрация должна идти на заранее
  прогретом прогоне, иначе прогоны не успеют в 10 минут.
- Не показывать длинные листинги: `pf log` — с прокруткой к основаниям.
- Не обещать в голос то, чего нет в журнале: всё на экране должно
  подтверждаться командой.
