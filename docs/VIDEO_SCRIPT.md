# Сценарий видеозаписи работы агента (до 10 минут)

Бриф требует: «Видеозапись работы агента до 10 минут — обязательно.
Сквозной путь демонстрационного проекта: запрос, работа агента,
варианты, стратегия, продолжение после перерыва».

Видео снимается с экрана терминала, голос не нужен: комментарии
накладываются текстом. Порядок — ровно тот, в котором агент реально
работает.

---

## Тайминг

Десять минут, семь сильных ходов. Голос не нужен: комментарии — текстом.
Порядок — тот, в котором агент реально работает.

| Время | Экран | Что показываем | Что это доказывает |
|---|---|---|---|
| 0:00-0:30 | терминал | `make doctor` | Запуск по инструкции без скрытых настроек |
| 0:30-1:00 | терминал | `pf run "Почему падает удержание…"` | Запрос вводится целиком; агент идёт сам |
| 1:00-2:30 | терминал | работа агента, 9 фаз | Основания и отклонения видны по ходу; проверка — код |
| 2:30-3:40 | терминал | итог: варианты, стратегия, план проверки | ≥3 разных варианта, возражения, продукт ↔ коммуникация |
| 3:40-4:40 | терминал | `pf report` | Доля подтверждённых, **стоимость по ролям** — оправдание каждого компонента |
| 4:40-5:30 | терминал | `pf log` | Отказ называет вид и владельца исправления («что чинить») |
| 5:30-6:20 | терминал | `pf review --session …` | **После решения**: новые данные → «требует пересмотра», а не «вывод неверен» |
| 6:20-7:00 | терминал | `pf stop`, затем `pf resume` | Продолжение с того же места (состояние на диске) |
| 7:00-7:40 | терминал | `pf eval` | Правила поведения проверяются, а не обещаются |
| 7:40-8:20 | терминал | `pf bench` | **Замер против baseline**: агент против обычного чата |
| 8:20-9:00 | терминал | `pf web "…" --parse`, `pf mcp …` | Внешнее — «требует проверки»; инструменты доступны из CLI |
| 9:00-9:40 | текст/слайд | «Где мы сознательно не строили агента» | Разрешение сущностей, извлечение, форматирование, маршрутизация — один вызов |
| 9:40-10:00 | терминал | `make ci` | 781 тест, eval 22/22, гейты документов и индекса |

---

## Что должно быть видно обязательно

1. **Запрос** — задача руководителя вводится целиком.
2. **Работа агента** — фазы идут сами, без вмешательства.
3. **Варианты** — минимум три, у каждого сильное возражение.
4. **Стратегия** — продуктовая, коммуникационная и план проверки.
5. **Стоимость по ролям** — каждый компонент оправдан, а не «их много».
6. **После решения** — `pf review`: что затронуто новыми данными.
7. **Продолжение после перерыва** — `pf stop`, затем `pf resume`.

## Комментарии, которые стоит наложить текстом

- «Факт без дословной цитаты отбрасывается. Это код, а не просьба модели.»
- «Агент называет пробелы: данных об оттоке в открытых источниках нет.»
- «Внешний источник проходит проверку, но его статус — требует проверки.»
- «Расход виден по ролям: видно, за что платишь, и что даёт каждая роль.»
- «Работа продолжается с того же места — состояние лежит на диске.»
- «Мы не строили агента там, где он не оправдан: это часть решения, а не пробел.»
- «Одна известная граница названа прямо: тождество сущностей отложено, модель записана.»

## Подготовка

```bash
make setup
ollama pull qwen3:8b
make doctor
# прогреть демо, чтобы на видео шло быстро:
uv run pf run "Почему падает удержание у мобильного тарифа и что с этим делать?"
# очистить журнал, чтобы в кадре были чистые цифры:
rm -f journal/session-demo*.jsonl state/session-demo*.json
```

Терминал: шрифт покрупнее, тёмная тема, окно на весь экран.

## Чего не делать

- Не запускать `make demo` вслепую: демонстрация должна идти на заранее
  прогретом прогоне, иначе прогоны не успеют в 10 минут.
- Не показывать длинные листинги: `pf log` — с прокруткой к основаниям.
- Не обещать в голос то, чего нет в журнале: всё на экране должно
  подтверждаться командой.
