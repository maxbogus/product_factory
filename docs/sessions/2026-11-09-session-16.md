## 1. Что было до работы

`pf report --session demo-v9` печатал «Основания вывода: подкреплено
(уникальных оснований: проверено 2, подтверждено 2, отклонено 0)» — в одном
документе с таблицей расчётов, где те же `#row0` и `#row1` стояли как
«отклонено», и с разделом «Отклонённые основания», где они названы отказом.

Причина нашлась в журнале: шаги 8–9 хранят
`{"checked": 4, "confirmed": 4, "rejected": 0, "status": "подкреплено"}` — без
ключей `grounds` и без имени правила. `report._journal_tally` достраивает счёт
по объявленным ссылкам, получает «2 из 2», и `conclusion_status` честно печатает
«подкреплено» — по правилу, которое снял `D-36`. Отчёт не врал: он повторял
запись и подавал её как текущую оценку.

Заодно проверено, какие «короткие» задачи такими не являются: `T-45` обещала
эмбеддинги (против `D-09` и замера `T-37`), `T-48` требует замера на пяти
журналах, `T-08` — проектирования ранжирования (`D-37`, критерий 3).

## 2. `T-47` — имя правила у статуса

**Красный прогон.** `-k stale_rule` и `-k conclusion_rule` →
`ImportError: cannot import name 'CONCLUSION_RULE'` (правила ещё нет).

**Правка.** `pf.ground.CONCLUSION_RULE_PARTS = ("unique-grounds",
"calc-line-demotion", "indicator-cap")` и `CONCLUSION_RULE` как их сумма через
`+`: части, а не номер версии — когда правило теряет часть, разница
называется. `Workflow._conclusion_verdict` пишет `rule` в блок статуса.

Отчёт (`pf.report`): `ConclusionRecord.rule` + `rule_is_current`; статус
подписан «по правилу прогона», если имя не записано или не совпало; названы оба
правила и `make replay`; `readiness()` говорит «Прогон даёт решение по прежнему
правилу». Противоречие внутри журнала (`_rejected_material_keys`): строка,
отклонённая на одном шаге и подтверждённая в выводе, названа ключами.

**Два решения по ходу, оба названы в `D-44`:**

1. подпись ставится только там, где статус **заявляет опору**
   («подкреплено», «подкреплено частично») — иначе `demo/RESULT.md`
   («ждут проверки») пришлось бы переписывать без пользы читателю;
2. статус не понижается автоматически по совпадению ключа: «значение
   посчитано, а не процитировано» и честная цитата из той же строки — разные
   утверждения, автопонижение дало бы ложные срабатывания.

## 3. `T-51` — допущения вывода

**Красный прогон.** `-k assumptions` в `test_schemas.py` → `AttributeError` /
`ValidationError` (поля нет), в `test_report_conclusion.py` — пустой блок.

**Правка.** `ProductStrategy.assumptions: list[str]` (пусто по умолчанию),
синонимы `допущения` / `предпосылки` / `what_must_be_true`, `as_text_list`,
плоский ответ; `prompts/roles/strategy.md` объясняет разницу с «осознанными
отказами»; отчёт печатает блок «Что должно быть верно, чтобы вывод работал».

Пробел назван: прогон текущим правилом без допущений печатает «Допущения вывода
не названы». Унаследованный журнал не судится — поля тогда не было.

## 4. `T-26` — arXiv отдельным каналом

**Красный прогон.** `tests/test_arxiv.py` не существовал.

**Правка.** `src/pf/arxiv.py`: `parse_atom` (пространство имён Atom, битая
запись пропускается, лимит), `search_arxiv` (сетевая ошибка → пустой список:
деградация, а не отказ). `SearchHit.peer_reviewed` едет с результатом.
`pf web --arxiv` — отдельная ветка, не канал в `search_web`: общий фильтр
считает основы русских слов и молча выбросил бы английские заголовки (`D-26`).
