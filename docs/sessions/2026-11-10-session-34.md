# Сессия 34 — свип модели, окна и бюджета контекста (T-75)

> **Дата:** 2026-11-10 · **Задачи:** T-75 (3 SP) ·
> **Итог:** `make ci` зелёный, 859 детерминированных тестов, eval 24/24.

## 1. Что сделано

- **Ось бюджета контекста параметризована.** `Settings.context_passages`
  (`PF_CONTEXT_PASSAGES`, по умолчанию 5) — отдельный рычаг от окна;
  `Workflow._bundle_context` берёт бюджет из настроек, а не из константы
  `CONTEXT_PASSAGES`. `.env.example` сведён с умолчанием.
- **Правило решения — чистые функции** `src/pf/role_sweep.py`:
  `decide_config` (умолчание окна, если чисто; иначе — чистое окно с меньшим
  бюджетом; иначе — меньшая обрезка), `decide_tiers` (проход схемы ≥ 2/3,
  затем обрезка, время, CPU, фантомы), `decide_sweep`, `load_snapshot` /
  `load_frozen`.
- **Харнесс** `scripts/grid_sweep.py` + `make grid-sweep`: матрица
  «модель × окно × бюджет», 3 повтора; каждая клетка — дочерний процесс
  (OOM убивает ребёнка); продолжение по `runs.jsonl`; heartbeat в
  `progress.log` раз в 30 с; память в `~/.cline/memory/ml-sessions.jsonl`;
  `--snapshot-only` собирает решение по готовым клеткам.
- **Заморозка:** `reports/role_sweep/decision.json`, `docs/decisions.md`
  `D-66`, `.env.example` (12b — только ≥12 ГБ).

## 2. Результаты замера (8 ГБ VRAM)

| Модель | Окно | ok | Медиана, с | Обрезка | `ollama ps` |
|---|---:|---:|---:|---:|---|
| `qwen3:8b` | 12288 | 3/3 | 278,0 | 0 | 100 % GPU |
| `qwen3:8b` | 8192 | 2/3 | 279,7 | 0 | 100 % GPU |
| `qwen3:8b` | 16384 | 2/3 | 268,4 | 0 | 100 % GPU |
| `mistral-nemo:12b` | 12288 | 0/1 | — | 0 | 25 % CPU / 75 % GPU |

**Решение:** окно `12288`, бюджет `5`, все ярусы — `qwen3:8b`.

1. **Обрезки нет ни на одном окне.** После `D-64` промпт влезает и в 8192:
   прежняя причина 12288 (analyst 9433, strategy 9560) на текущем контенте
   снята. Умолчание 12288 оставлено: все окна чистые, менять без нужды
   нельзя.
2. **12b на 8 ГБ не годится.** 25 % CPU, ответ не приходит за 180 с,
   `LLMError` после двух попыток. Выбор `T-73` (синтез на 12b) для этой
   машины отменён.
3. **Падения — таймауты, а не обрезка.** Клетки 8192/16384 упали с
   `truncated=0` из-за `timeout_seconds=180`; разброс времени — свойство
   машины.
