# Сессия 5 — 2026-11-08

**Цель сессии:** убрать ложные подтверждения и вытеснение контекста — то,
из-за чего ответ на вопрос был формально «подкреплён», а по существу не
отвечал на заданный вопрос.

**Взятые задачи:** `T-15` (2 SP), `T-16` (2 SP), `T-18` (1 SP) — три звена
одной цепи, каждое закрыто отдельным коммитом.

## Что было не так

Разбор `demo-v9` показал цепь из пяти звеньев, и три из них — код, а не
модель:

| Звено | Факт |
|---|---|
| Контекст | Окно из пяти абзацев целиком состояло из строк таблицы: `collect()` ставит материалы перед корпусом, а каждая строка CSV — отдельный цитатуемый абзац. Абзацев Википедии про отток модель не видела вообще |
| Ответ модели | «Удержание клиентов составляет 87 %» при строке «МТС, абонентская база, 87» |
| Проверка | `verify_claim(#rowN)` при неудачном дословном поиске подтверждал основание, если число из цитаты есть в строке — показатель не сверялся |
| Вывод | Статус «подкреплено» на двух якорях, которые в том же прогоне были **отклонены** как метрики |
| Отчёт | «Доля подтверждённых 60 %» по записям при двух уникальных основаниях |

Живая проверка до работы (текущий код, сохранённые данные):

```
[confirmed] Удержание пользователей мобильного тарифа снизилось …
[confirmed] Внедрение гибкого тарифа повысит удержание на 5 %
[confirmed] Удержание клиентов составляет 87 %
            почему: «значение из расчёта найдено в строке таблицы»
```

## Чем проверено

```
uv run pytest tests/test_sources.py -k indicator -q          → 2 failed до правок, 4 passed после
uv run pytest tests/test_retrieval.py -k context -q          → 1 failed до правок, 2 passed после
uv run pytest tests/test_conclusion_grounding.py -k rejected_metric -q
                                                             → 2 failed до правок, 3 passed после
uv run pytest tests/ -m "not slow" -q                        → 518 passed, 4 deselected
uv run python scripts/replay_verification.py --sessions demo-v9
                                                             → подтверждено 0, нет данных 16,
                                                               требует проверки 4, контрольные пробы 6 из 6
make ci                                                      → зелёный целиком
```

Первая правка `_stems` (собственный регэксп) уронила
`test_metric_name_must_match_column`: скобки не отбрасывались, и метрика
«Удержание клиентов (МТС, абонентская база)» проходила по слову «база» из
скобок. Правильная правка — наследовать правило от `_significant_words`, а
не повторять разбор текста. Красный прогон поймал это до коммита.

## Честные оговорки

- **Хорошая новость и плохая одновременно:** после правок `demo-v9` даёт
  **0 подтверждённых оснований из 20**. Это не регресс: в том прогоне не
  было ни одного основания про удержание — только абонентская база. Честный
  ответ на вопрос «почему падает удержание» по этим данным — «причина не
  установлена», и он требует данных (T-11), а не ещё одной правки проверки.
- **`make replay` не связывает состояние между шагами**, поэтому эффект
  `T-18` в нём не виден: харнесс перепроверяет каждый шаг отдельно. Связь
  «отказ на разборе → вывод в стратегии» держат юнит-тесты. Расширить
  replay до переноса состояния — отдельная задача.
- **Остаточный дефект отбора строк:** строки всё ещё отбираются по
  совпадению слов, поэтому в окно попадают «МТС Беларусь 2026» и «доля на
  рынке спутникового ТВ». Это `T-25` — отбор, а не композиция окна.
- **Демонстрационный документ устарел по смыслу:** `demo/RESULT.md`
  собран из журнала `demo-v9` и показывает прежние подтверждения. Его надо
  пересобрать после нового прогона (`make demo`, затем
  `make demo-doc SESSION=demo-v10`), а не править руками.
- **Числа канона менялись трижды** (513 → 515 → 518) — по одному разу на
  коммит, чтобы `make ci` был зелёным на каждом.

## Что осталось

- `T-17` (2 SP): числа плана и обязательств сверяются с расчётами.
- `T-25` (2 SP): строка таблицы отбирается по показателю, а не по словам.
- `T-20`/`T-21` (3 + 1 SP): пауза с вопросом человеку и настоящий `pf stop`.
- `T-11` (3 SP): данные по оттоку, ARPU и конкурентам — без них честный
  ответ остаётся «причина не установлена».
