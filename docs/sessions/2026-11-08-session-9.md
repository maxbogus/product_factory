## 2. Найдено по ходу (и это важнее, чем задачи)

1. **Сводные метрики отбрасывались все.** В первом прогоне `demo-v10`
   подтверждённых расчётов было ноль, и причина оказалась не в данных:
   блок РАСЧЁТЫ печатает наблюдения через запятую, модель копирует строку
   как есть, а `_input_numbers` видел одну нечисловую строку — пересчёт не
   запускался, и метрика падала на сверке со строкой 0. Исправлено
   (`_split_numbers`: разделители только вместе с пробелом, чтобы «78,5» не
   стало двумя числами), регресс —
   `test_aggregate_copied_as_text_still_confirms`. После исправления те же
   три метрики подтверждаются пересчётом, и прогон повторён.
2. **Первый прогон шёл дважды.** Два фоновых запуска писали в один журнал:
   шаги дублировались по номерам. Замечено по повторяющимся `ordinal`, оба
   процесса сняты, журнал и состояние очищены, прогон выполнен один раз.
   Вывод на будущее: после `setsid` проверять число процессов, а не только
   наличие лога.
3. **Период-квартал ломает порядок.** `analysis._period_key` разбирает
   «1 кв. 2017» как число `12017` и ставит первый квартал 2018 года раньше
   четвёртого квартала 2017-го. Поэтому в данных периоды приведены к
   `2017-Q1`; править `_period_key` — отдельная работа.
4. **mypy увидел то, чего не видел раньше.** После установки набора
   `documents` типы `pdfplumber` и `docx` стали известны, и одна и та же
   переменная `document` в двух ветках `_read_document` дала ошибку типов.
   Переменные переименованы (`pdf`, `word`).

## 3. Честные оговорки

- **Прямого ряда оттока нет.** Проверено тремя путями: поиск по Википедии
  (`insource:"отток" абонент` — 19 попаданий, ни одного телеком-числа),
  годовой отчёт (86 страниц: «отток» только как следствие рисков), сайты
  операторов. Файл `telecom_churn_open.csv` не создан; прокси «чистое
  изменение базы» как «отток» не введён (`D-31`).
- **Тарифы конкурентов не получены:** МТС — 401, T2 — 503, Билайн отдаёт
  страницу без цен. Снимок МегаФона остаётся «требовать проверки».
- **Вывод `demo-v10` не подкреплён:** 0 из 2 оснований. Модель цитирует
  средние как строки источника, а средняя величина проверяется пересчётом
  по входам, которых в цитате нет. Это заведено задачей `T-30` — новая
  работа, а не скрытый дефект.
- **Доля подтверждённых упала** с 60 % до 21 %: данных стало больше, и
  выросло число цитат, которые проверка отвергла. Абсолютное число
  подтверждённых оснований выросло (2 → 3), а расчётов — с 0 до 2.
- **`make setup` не тронут:** фрагмент отчёта читается только с
  `uv sync --extra documents`; без набора документ попадает в «Пропущено»
  с причиной.
