## Что сделано в сессии 4

1. **`T-02` закрыта.** Полюса вариантов проверяет схема, а не обработчик
   кейса: `Variants._poles` (`src/pf/schemas.py`) требует вариант «оставить
   как есть» и вариант «закрыть направление» **в наборе**, а маркеры выводит
   из фактических названий. Набор без полюса отклоняется с текстом, который
   называет, какого полюса нет, и какие формулировки допустимы.
2. **Кейсы `D-05`, `D-06`, `D-09` перестали быть тавтологиями.** Обработчики
   возвращали ровно ту строку, которую кейс искал: `D-05` печатал «Закрыть
   направление» при любом поведении схемы. Теперь текст приходит из отказа
   схемы, а запасной текст обработчика искомой подстроки не содержит.
3. **Заявление прошлой сессии оказалось неверным.** HANDOFF утверждал, что
   «все сохранённые прогоны заполняли оба маркера». Аудит 25 прогонов с
   `results.options`: в 2 маркер «Закрыть направление» стоял при наборе, где
   такого варианта нет; ещё в 1 оба маркера пустые, а полюса в вариантах
   есть. Поэтому проверка идёт по вариантам — маркер это утверждение модели о
   своём же ответе (`docs/decisions.md`, D-23). Текст исправлен здесь. Проба
   «прогнать сохранённые наборы через новую схему»: 22 из 25 приняты, 2 отказа
   по полюсам и 1 по пустым возражениям первого варианта (к полюсам отношения
   не имеет).
4. **Две ловушки поймали красные прогоны.** Первая: запасной текст
   обработчика содержал искомую подстроку — кейс оставался зелёным при
   выключенной проверке. Вторая: общий текст отказа перечисляет оба полюса,
   поэтому широкая подстрока «оставить как есть» совпадала и в отказе из-за
   другого полюса. Теперь кейсы проверяют конкретную фразу, а регресс держит
   `tests/test_eval_cases.py::test_cases_d05_d06_go_red_without_pole_check`.
5. **Синонимы формулировок — константы схемы**, а не данные
   `knowledge/lexicon`: словарь знаний имеет статусы и подтверждается
   человеком, а форма ответа должна проверяться без файлов.
6. **Реестр и карточка.** `architecture/rules/implementation-status.yaml` —
   запись `variant-poles` (гейт `implemented-means-module-and-test`),
   карточка `docs/tasks/T-02.md` с ценой строгости: 2 из 25 исторических
   наборов полюса не имели, такой шаг повторяется с подсказкой.

## Где остановились

- `src/pf/schemas.py` — `KEEP_CURRENT_TITLES`, `CLOSE_DIRECTION_TITLES`,
  `pole_of`, `Variants._poles`: полюса проверяются по названиям вариантов, а
  маркеры выводятся из них. Правится вместе с `tests/test_schemas.py`
  (блок «Полюса вариантов»). Порядок валидаторов важен: `_diverse` идёт
  **до** `_poles`, иначе «одинаковые названия» сообщались бы как «нет полюса».
- `src/pf/evalrun.py` — обработчики кейсов возвращают **текст схемы**, а
  запасной текст обработчика не должен содержать подстроку, которую ищет кейс.
  Иначе кейс зеленеет при выключенной проверке (так и было). Регресс —
  `tests/test_eval_cases.py::test_cases_d05_d06_go_red_without_pole_check`.
- `src/pf/workflow.py` — ветка `_repair_prompt` для отказа «нет полюса»:
  формулировки берутся из констант схемы, а не переписываются в подсказке.
- `src/pf/ground.py` — `citation_key`, `ground_buckets`, `tally_grounds`,
  `conclusion_status`: правило счёта оснований и статуса вывода. Правится
  только вместе с `tests/test_ground.py` и
  `tests/test_conclusion_grounding.py`.
- `src/pf/report.py` — `_journal_tally`: три случая чтения журнала
  (ключи есть / ключей нет и отказов нет / ключей нет и отказы есть).
- `docs/canon.py` — числа; изменили число тестов → сначала `make canon`,
  потом документы (518 сейчас).
- `tests/test_documents_consistency.py` — заявления документов против кода:
  умолчания `.env.example` берутся из `Settings.model_fields[...].default`
  (не из `Settings()` — иначе локальный `.env` подменит эталон), команды —
  из `pf.cli.build_parser()` и Makefile. Правится только вместе с
  `tests/test_ci_config.py` (он тоже читает `.env.example`).
- `scripts/tasks_gate.py`, `scripts/docs_check.py`, `scripts/next_task.py` —
  гейты процесса; красные прогоны в `tests/test_tasks_gate.py` и
  `tests/test_docs_check.py`.
