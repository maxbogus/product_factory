# Стратег Фабрики продуктов — описание работы

Документ закрывает требование брифа: «Описание работы — PDF или документ
по ссылке, со скриншотами: архитектура агента; полный перечень моделей,
сервисов и инструментов; ключевые промпты; какие возможности
дополнительного уровня реализованы; время и примерные расходы; ошибки и
помощь человека; заявленные возможности и их ограничения».

---

## 1. Что это

ИИ-агент для руководителя цифрового продукта: проводит исследование,
проверяет основания, предлагает варианты, вырабатывает продуктовую и
коммуникационную стратегию с планом проверки — и продолжает работать
после решения.

Ядро — **папка с файлами**: инструкции ролей (`prompts/roles/`),
методические знания (`methods/`), повторяемые процедуры (`skills/`),
субагенты (`subagents/`), материалы проекта (`project/`) и состояние
задачи (`state/`, `journal/`). Плюс небольшой Python-рантайм
(`src/pf/`), который эти файлы исполняет.

Ключевое отличие от обычного чата: **каждое утверждение проверяется
кодом**. Цитата должна дословно встречаться в источнике; иначе основание
отбрасывается, а отклонение попадает в журнал с причиной.

---

## 2. Архитектура

### 2.1 Рабочий процесс

```
INTAKE → PLANNING → ROUTING → COLLECTING → ANALYZING
       → OPTIONS → REDTEAM → STRATEGY → KEEPER → DONE
```

Девять фаз, у каждой — своя роль (файл промпта + схема ответа).
Автомат останавливается там, где без решения человека работа потеряла бы
смысл: `need_human` роутера превращает вопрос в `pending_question`,
ответ человека (`pf answer`) возвращается в контекст следующего шага.

### 2.2 Работа с контекстом

| Слой | Где | Что внутри | Как попадает в модель |
|---|---|---|---|
| Постоянные инструкции | `prompts/roles/*.md` | Правила каждой из 9 ролей | Системный промпт роли |
| Методические знания | `methods/*.md` | Факт/гипотеза, варианты, стратегия, план проверки | Подставляются в промпт своей роли |
| Процедуры (скилы) | `skills/*.md` | Сбор источников, модельные респонденты | Подставляются в промпт своей роли |
| Материалы проекта | `project/`, `data/wiki/` | Корпус Википедии (8 066 статей, 11 разделов) | Отобранные абзацы — в блок «МАТЕРИАЛЫ» |
| Внешние источники | Интернет (RSS, Bing News) | Новости и статьи | Отдельным блоком «ВНЕШНИЕ ИСТОЧНИКИ» |
| Состояние задачи | `state/`, `journal/` | Фаза, результаты, расход | Читается при продолжении |

Отдельный блок для внешних источников — не украшение: у них другой
статус подтверждения, и смешивать их с локальными основаниями нельзя.

Окно контекста задаётся явно (`PF_OLLAMA_NUM_CTX`, по умолчанию 12288).
Без этого Ollama берёт 4096 и молча обрезает начало промпта; теперь
признак обрезки виден в журнале шага (`detail["context"]`) и в отчёте
строкой «Промпт упёрся в окно» (D-20).

### 2.3 Проверка оснований — главный механизм честности

1. **Цитата** должна дословно встречаться в исходном тексте статьи
   (`src/pf/ground.py`).
2. Если цитаты нет — проверяется покрытие абзацем (порог 80 %
   значимых слов). Слова сравниваются **по леммам и словарю близости**:
   «клиенты» в утверждении покрываются «абонентами» источника
   (`src/pf/lexical.py`, `src/pf/synonyms.py`).
3. **Числа сверяются с допуском** до десятой доли: «77,3» подтверждает
   «77,26» — это округление, а не подмена. Для величин меньше единицы
   абсолютный допуск не включается.
4. **Точные термины не заменяются**: числа, бренды, аббревиатуры и
   латиница вне словаря обязаны совпасть. Подмена «МТС» на «МегаФон»
   отклоняется даже при совпадающем окружении. Добавленное отрицание
   («не падает» вместо «падает») тоже отклоняется.
5. **Источник должен относиться к задаче**: настоящая цитата из
   посторонней статьи основанием не является (`src/pf/sources.py`).
6. Что не прошло — попадает в журнал как отклонённое основание с
   причиной. «Требует проверки» — отдельный исход и отдельный раздел
   отчёта.

Внешние (веб-) источники проходят проверку дословности по скачанной
странице, но их статус **всегда** «требует проверки»: `confirmed` для
них недостижим. Русская цитата на иностранной странице тоже получает
«требует проверки»: дословный перевод не проверяется, сверяются числа.

**Незнакомые слова не теряются.** Слово, которого нет в словаре и не
знает морфология, пишется в очередь распознания
(`knowledge/lexicon/oov.jsonl`, append-only). `pf lexicon enrich`
предлагает понятие, человек подтверждает — и только тогда словарь
влияет на проверку. Отчёт показывает лексическое покрытие и топ
незнакомых слов.

**Лимит ответа.** Модель видит бюджет ответа заранее (токены и
ориентир в символах), а также явный лимит из задачи («не более 200
слов»). Ограничения задачи передаются в запрос каждой роли.

### 2.4 Маршрутизация

Роутер выбирает, кто работает следующим, и его решение влияет на ход
работы. Ошибочный выбор исправляется (`src/pf/workflow.py`):

| Ошибка роутера | Что делает агент |
|---|---|
| Неизвестная роль | Идёт по порядку фаз, пишет причину в состояние |
| Откат назад | Отбрасывает маршрут, идёт по порядку |
| Зацикливание (та же фаза) | Берёт следующую фазу |

## 3. Модели, сервисы и инструменты

| Что | Версия / где | Зачем |
|---|---|---|
| **Локальная модель (по умолчанию)** | `qwen3:8b` через Ollama 0.17 | Работа агента. Бесплатно, без ключей, без сети |
| **Модель побольше** | `qwen3:8b` (5.2 ГБ) | То же, но заметно больше подтверждённых оснований (5 против 0-2) |
| **12B-альтернатива** | `mistral-nemo:12b` (7.1 ГБ) | Влезает в 8 ГБ VRAM; русский средний, цитат меньше |
| **Облачная модель (опция)** | Любой OpenAI-совместимый API, включая DeepSeek (`deepseek-flash`, `deepseek-v4-pro`) | Сравнение качества: облако даёт больше за те же центы |
| **Корпус** | Википедия, 8 066 статей, 11 разделов (`data/wiki/`) | Источник цитат. Лицензия CC BY-SA 4.0, атрибуция в `data/wiki/SOURCE.md` |
| **Поиск в интернете** | RSS-ленты (ТАСС, Ведомости, РГ, Коммерсант) + Bing News | Дополнительные материалы, когда локальных оснований не хватает |
| **Разбор страниц** | `bs4` + `robots.txt` (stdlib) | Извлечение абзацев, пригодных для цитирования |
| **MCP** | `static-parser` (6 инструментов) из соседнего `mcp-servers` | Разбор страниц, метаданные, проверка robots |
| **Трекинг замеров** | MLflow (файловая база) + JSONL | Накопитель измерений для сравнения с обычным чатом |
| **Тесты** | pytest, ruff, mypy --strict | 569 детерминированных + 4 живых теста с моделью |

Внешние зависимости минимальны: `httpx`, `pydantic`, `scikit-learn`,
`pymorphy3`, `beautifulsoup4`. Нет `torch`, нет векторной базы, нет
веб-фреймворка — образ весит десятки мегабайт.

## 4. Ключевые промпты и инструкции

Все девять ролей — обычные текстовые файлы, которые правятся без
перезапуска:

| Файл | Роль | Что задаёт |
|---|---|---|
| `prompts/roles/intake.md` | Постановка задачи | Цель, получателя, ограничения; не больше трёх вопросов |
| `prompts/roles/planner.md` | План исследования | Вопросы, ответы на которые могут изменить решение |
| `prompts/roles/router.md` | Маршрутизация | Кто работает следующим; когда звать человека |
| `prompts/roles/collector.md` | Сбор источников | Взять факты из отобранных абзацев, не сочинять |
| `prompts/roles/analyst.md` | Разбор | Факты отдельно от гипотез и прогнозов; назвать пробелы |
| `prompts/roles/options.md` | Варианты | Минимум три содержательно разных, у каждого — возражения |
| `prompts/roles/redteam.md` | Критика | Что не так с каждым вариантом |
| `prompts/roles/strategy.md` | Стратегия | Продуктовая, коммуникационная, план проверки |
| `prompts/roles/keeper.md` | Фиксация | Обязательства, показатели, условия пересмотра |

Методики (`methods/*.md`) — общие правила работы; скилы
(`skills/*.md`) — повторяемые процедуры; субагент
(`subagents/fact-check.md`) — узкая перепроверка оснований.

Полный пример инструкции с подставленными методиками и скилами —
`pf log` и `src/pf/roles.py`.

## 5. Реализованные возможности дополнительного уровня

| Возможность | Статус | Как сделано |
|---|---|---|
| **Анализ данных (расчёты)** | **да** | `src/pf/analysis.py`: median, mean, percentile, изменение, CAGR. Каждая метрика несёт источник, строку, формулу и входные значения; **проверяется пересчётом по строке** — число нельзя «процитировать», его можно только посчитать заново |
| **Свои документы и таблицы** | **да** | `src/pf/materials.py`: `.md`, `.txt`, `.csv`, `.tsv`, `.json`, `.pdf`, `.docx`, `.xlsx`. Строка таблицы становится цитатуемым абзацем с идентификатором `project/<файл>#rowN`. Чтение `.pdf`, `.docx` и `.xlsx` требует набора библиотек — `uv sync --extra documents`; в базовом окружении такие файлы пропускаются |
| **Отчёт по прогону с числами** | **да** | `pf report`: основания, доля подтверждённых, расход по ролям, обязательный раздел «чего этот замер не показывает», а также **контроль качества**: отказы по классам, доля расчётов с формулой, решения роутера и результат повторной проверки субагентом |
| **Документ демонстрации** | **да** | `scripts/build_demo_doc.py` собирает `demo/RESULT.md` из журнала: подтверждённые основания — только те, что код подтвердил и ни разу не отверг; у каждого расчёта видна формула или честная пометка, что её нет; раздел «Вывод» отвечает на заданный вопрос и показывает статус своих оснований. Тест сверяет документ с журналом |
| **Проверка оснований вывода** | **да** | `src/pf/workflow.py`: `evidence` продуктовой стратегии, `promise_grounding` коммуникации и `basis` обязательств проходят ту же проверку, что факт — дословность цитаты и релевантность источника. Статус (`подкреплено` / `частично` / `неподкреплено`) пишется в журнал шага и в отчёт. Ограничение: смысловая поддержка по-прежнему не проверяется — только дословность и релевантность |
| **Имя показателя против колонки** | **да** | `src/pf/sources.py`: если строка таблицы сама называет показатель («показатель: абонентская база»), метрика не может называть его иначе — «удержание» поверх абонентской базы отклоняется. Формула-тождество («Сумма / количество» по одному наблюдению) расчётом не считается |
| **Противоречия между фактами** | **да** | Два подтверждённых факта, говорящие разное об одном показателе («удержание падает» и «удержание не изменилось»), объявляются пробелом и видны в отчёте |
| **Вердикт гипотез** | **да** | `supported` / `refuted` / `unknown` ставит код по подтверждённым основаниям: совпадение предмета и направления — поддержано, противоположное направление — опровергнуто, иначе «требует проверки». Отчёт называет все три числа. Целевого добирания оснований по `unknown` пока нет (T-08) |
| Интервью и модельные респонденты | частично | `skills/mock-respondents.md` подключён к аналитику, синтетика помечается; **отдельной фазы интервью нет** — процедура описана, но не исполняется как шаг |
| Маршрутизация | да | Роутер выбирает фазу и исправляет ошибочный выбор; русские названия ролей («план», «Сбор источников») понимаются, а решение и его исправление попадают в журнал и отчёт. Ограничение: роутер вызывается один раз — на фазе `ROUTING` (см. D-15) |
| Навыки | да | `skills/*.md` подставляются в промпт своей роли: сбор источников, расчёты, модельные респонденты |
| Хуки | да | `hooks/sources.yaml`: `sources.collected`, `budget.exhausted` — выполняются в коде |
| Субагенты | да | `subagents/fact-check.md`: перепроверка оснований с другой стороны |
| Интеграции через MCP и CLI | да | 6 серверов: разбор страниц, документы и OCR, слепки интерфейсов, скриншоты, поисковый спрос. `pf mcp <сервер> <инструмент>` |
| База знаний | да | TF-IDF по леммам, доменные термины отобраны замером по корпусу; **хранилище знаний** `knowledge/raw/<дата>/` с манифестом и хешами версий. В нём — снимок публичных тарифов МегаФона (`2026-11-07/`) и фрагмент годового отчёта ПАО «ВымпелКом» за 2025 год (`2026-11-08/`, `.docx`, три страницы: перенос номера и реестр ключевых рисков) — внешние данные, статус «требует проверки». Материалы проекта `project/data/` содержат открытые метрики: абонентская база, ключевая ставка, ARPU ВымпелКома по кварталам 2017–2018, заявки на перенос номера (ЦНИИС) |
| Устойчивость к сбоям | да | Повторы с подсказкой о конкретной ошибке; сбойный шаг не повторяется вслепую; работа продолжается после сбоя |
| Переносимость | да | Состояние — текст на диске, без абсолютных путей; конфигурация через переменные; готовые конфиги для Cursor и GigaCode |
| Сравнение с исходным способом | да | `scripts/bench.py`: агент против обычного чата, накопитель MLflow |
| A/B самой проверки оснований | да | `scripts/replay_verification.py`: проверка повторяется на сохранённых результатах ролей (данные те же, меняется только код), плюс шесть контрольных проб. Снимок с вердиктами по каждому основанию сравнивается с прежним (`--compare`) — видно не только «сколько», но и «какие переехали» |
| Анализ пользовательского опыта | частично | MCP-сервер `ux-snapshot` подключён и работает; **разбор снимков в рабочем процессе не автоматизирован** — им можно пользоваться через `pf mcp` |
| Изображения, аудио, видео | нет | Не реализовано. Сервер `vision` подключён, но агент не использует его сам |
| Пересмотр при новых данных | **да** | `pf review --session <id>`: `pf.review.review_session` сравнивает записанный хеш с текущим файлом (выгрузки — по манифесту `knowledge/raw/<дата>/`, материалы проекта — по `<файл>.meta.json`) и называет затронутые шаги и обязательства. Четыре состояния различимы: «не изменилось», «требует пересмотра», «файл отсутствует», «хеш не записан». Пометка — «требует пересмотра», а не «вывод неверен»: хеш меняется и при косметической правке. Журнал не переписывается |

Что не реализовано — указано прямо, а не спрятано: бриф требует честно
называть границы.

## 6. Время и расходы

Полный прогон демонстрационной задачи на `qwen3:8b` (актуальный замер):

| Показатель | Значение |
|---|---|
| Фаз | 9 |
| Токенов | 53 335 |
| Время | ~8 мин на CPU (включая загрузку корпуса) |
| Стоимость | 0,053335 условных единиц (1 единица = 1 000 000 токенов) |
| Денег | **0 рублей** — локальная модель |
| Записей подтверждено | 6 |
| Уникальных оснований | 3 (абонентская база, ключевая ставка, ARPU) |
| Оснований отклонено | 23 |
| Доля подтверждённых | 21 % |
| Расчёты | 2 из 2 подтверждены пересчётом (средняя ставка, средний ARPU) |
| Основания вывода | не подкреплён: 0 из 2 — модель процитировала средние как строки, а средняя величина проверяется пересчётом по входам (T-30) |

Разбивка расхода по ролям — в `reports/sessions/session-demo-v10.md`,
его собирает команда `pf report --save`. Документ `demo/RESULT.md`
генерируется из того же журнала — `make demo-doc SESSION=demo-v10` —
поэтому он не может разойтись с прогоном.

С облачной моделью тот же прогон стоит **$0.005-0.03** (`deepseek-flash`:
$0.15 за 1M входных токенов off-peak, $0.60 за 1M выходных).

Разброс между прогонами велик: на одной задаче агент находит от 0 до 7
уникальных подтверждённых оснований. Поэтому честное сравнение требует
нескольких прогонов — их и делает `scripts/bench.py`.

**Что эти цифры не показывают** — в `pf report` (раздел «Чего этот замер
не показывает») и в `demo/RESULT.md`: подтверждение основания — это
дословное совпадение, а не смысловая поддержка; доля подтверждённых не
измеряет полноту; условные единицы — это токены, а не деньги.

## 7. Ошибки и помощь человека

| Ситуация | Что происходит | Помощь человека |
|---|---|---|
| Модель не ответила или обрезала JSON | Повтор с подсказкой формата (до 3 попыток) | Не нужна |
| Цитата не найдена в источнике | Основание отброшено, причина в журнале | Не нужна |
| Источник не относится к задаче | Основание отброшено | Не нужна |
| Локальных оснований мало | Хук `sources.collected` расширяет план, агент идёт в интернет | Не нужна |
| Разошлись два равноценных варианта | Роутер ставит `need_human`, агент спрашивает | **Нужна** |
| Расход достиг предела | Хук `budget.exhausted` останавливает работу с отчётом | **Нужна** |
| Сайт запретил обход в `robots.txt` | Страница пропускается | Не нужна |
| Интернет недоступен | Агент работает на локальном корпусе | Не нужна |

Помощь человека: **0 вопросов** на демонстрационной задаче; при
существенном выборе — один вопрос, ответ возвращается в контекст.

## 8. Заявленные возможности и ограничения

**Заявлено и работает:**

- сквозной путь от запроса до стратегии без ручных обходов;
- каждое утверждение проверяется дословным поиском по источнику;
- отклонённые основания видны с причиной;
- работа останавливается и продолжается с сохранённого места, в том
  числе в новом чате;
- расход виден по ролям; журнал — append-only;
- поиск в интернете с разбором страниц; внешнее никогда не выдаётся за
  подтверждённый факт;
- измерение «агент против обычного чата» на накопителе прогонов.

**Ограничения — честно:**

- **Данных об оттоке в открытых источниках нет.** Википедия и новости
  дают рыночный контекст (операторы, тарифы, конкуренция), но не
  внутреннюю телеметрию. Агент называет это пробелом — это часть
  демонстрации, а не её провал.
- **Качество зависит от модели.** 7B даёт 0-2 основания, `qwen3:8b` —
  до 5 на той же задаче. Разброс велик, поэтому все сравнения — среднее
  по нескольким прогонам.
- **Поиск в интернете неполон.** DuckDuckGo, Brave, Яндекс и SearXNG
  отдают анти-бот или лимит; рабочие каналы — RSS-ленты и Bing News.
  Обычная веб-выдача Bing по HTTP частично отдаёт результаты из чужого
  кэша, поэтому она только запасная и фильтруется по теме.
- **MCP-серверы живут в соседнем репозитории** (`mcp-servers`) и
  запускаются в своём окружении; `parser-storage` требует PostgreSQL и
  не проверен.
- **Проверка цитат ловит пересказ, а не ложь по смыслу.** Цитата из
  настоящей статьи проходит. Поэтому проверяется ещё и релевантность
  источника задаче — но и это не гарантия истинности.
- **Фильтр доменов настроен на телеком.** Для другой предметной
  области термины нужно расширить (`DOMAIN_TERMS` в `src/pf/corpus.py`).

## 9. Как запустить

```bash
make setup                                   # зависимости
ollama pull qwen3:8b                         # модель (5.2 ГБ)
make doctor                                  # проверка окружения
make demo                                    # демонстрационная задача
uv run pf log                                # журнал: основания и отклонения
uv run pf cost                               # расход по ролям
uv run pf web "отток абонентов" --parse     # поиск в интернете и разбор
uv run pf mcp static-parser                  # инструменты MCP
```

Полезное:

```bash
make test          # 569 детерминированных тестов
make test-slow     # живые тесты с моделью
make bench         # замеры: агент против обычного чата
make ci            # всё вместе
```
