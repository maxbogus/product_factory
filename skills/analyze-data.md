# Skill: воспроизводимые расчёты по данным

## Когда использовать

Когда в материалах есть числа — таблицы, выгрузки, метрики — и по ним
нужно обосновать вывод или план проверки. Обещание «повышение на 5–10 %»
без baseline — не план, а мечта: его нельзя ни проверить, ни пересчитать.

## Что делать

1. **Найди числа в материалах.** Таблица в `project/` — это строки с
   колонками; значение лежит в конкретной ячейке. Не пересказывай число
   из текста модели — считай по строке.
2. **Считай, а не оценивай.** Доступны расчёты модуля `pf.analysis`:
   `median`, `mean`, `percentile`, `change_percent`, `cagr`. Для русских
   данных число разбирается само: «11,923 млн» → `11.923`.
3. **У каждой метрики — provenance.** Источник (`source_id`), номер
   строки (`row`), формула и входные значения. Метрика без источника
   невоспроизводима: её нельзя пересчитать, а значит, нельзя проверить.
4. **База — первое наблюдение.** Изменение считается от первого
   наблюдения ряда, а не от «текущего уровня» в чужом источнике.
5. **Разные периоды не складываются.** Метрики разных операторов и разных
   лет — это контекст рядом, а не один ряд. Складывать их в тренд нельзя.
6. **Неполноту данных показывай.** Если значения нет («н/д»), метрика не
   считается: пропуск называется, а не заполняется средним.

## Чего нельзя

- Не выдумывать числа, которых нет в материалах.
- Не выводить процент без базы: «+10 %» от чего — вопрос без ответа.
- Не смешивать разные единицы и разные периоды в одном расчёте.
- Не называть оценку модели расчётом: «по нашим данным отток вырос» —
  это расчёт; «по нашим данным отток, вероятно, вырос» — оценка.

## Метрики / проверка

- У каждой метрики есть источник, строка и формула.
- Значение метрики пересчитывается из указанных входных.
- В ответе метрики отделены от фактов: факт — дословная цитата, метрика —
  число со ссылкой на строку.
