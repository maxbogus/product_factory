# Лексикон: словарь близости и очередь распознания

Каталог отвечает за то, чтобы проверка оснований понимала слова, а не
только строки: «абоненты» и «клиенты» — одно понятие, «77,3» — округление
«77,26».

## Файлы

| Файл | Коммитится | Правило записи | Что внутри |
|---|---|---|---|
| `synonyms.yaml` | да | переписывается целиком | словарь понятий: `canonical` + `aliases` |
| `oov.jsonl` | нет | **append-only** | очередь незнакомых слов и событий по ним |
| `manifest.jsonl` | да (если появится) | append-only | provenance пополнений словаря |

`oov.jsonl` — след работы, а не часть поставки, поэтому он в
`.gitignore`. Он не теряется между запусками: очередь нужна, чтобы
расширять словарь постепенно.

## Как расширять

```bash
pf lexicon oov                      # что накопилось и ждёт распознания
pf lexicon enrich --dry-run         # предложения модели, без записи
pf lexicon enrich                   # записать предложения (status: proposed)
pf lexicon oov --approve <слово>    # подтвердить (status: approved)
pf lexicon stats                    # покрытие и топ незнакомых слов
```

Порядок обязателен: **проверка оснований читает только `approved`**.
Запись `proposed` видна человеку, но в проверке не участвует — иначе
подтверждение основания снова стало бы самооценкой модели.

## Что считается распознанным

1. Слово есть в словаре (`approved`) — `known`.
2. Слово знает морфология (`pymorphy3`, `is_known`) — `resolved_morph`.
3. Сработала эвристика: гомоглифы (`удержаниe` → `удержание`),
   транслитерация (`megafon` ↔ `мегафон`), опечатка (расстояние ≤ 1) —
   `resolved_heuristic`.
4. Ничего не сработало — `oov`, слово уходит в `oov.jsonl`.

Эвристика никогда не применяется к точным терминам (числа, бренды,
аббревиатуры, латиница вне словаря): подмена термина меняет смысл
утверждения.

## Покрытие

`pf lexicon stats` показывает долю распознанных слов. Это измеримый
результат работы с очередью: после `approve` покрытие растёт, и это
видно в отчёте по прогону.
