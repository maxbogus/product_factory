# Стратег Фабрики продуктов

ИИ-агент, который помогает руководителю цифрового продукта пройти путь от
размытого запроса до обоснованной продуктовой и коммуникационной стратегии —
и не бросает его после того, как решение принято.

```
запрос  →  разбор источников  →  варианты  →  стратегия  →  обязательства
                        ↑                                        │
                        └────────────  новые данные  ←───────────┘
```

## Что это

Агент — это **папка с инструкциями, знаниями и инструментами**. Он не
работает как «чёрный ящик»: каждое его действие записано в журнал, у каждого
утверждения есть основание, а отсутствие данных он называет прямо.

Главное отличие от обычного чата с ИИ:

| Обычный чат | Этот агент |
|---|---|
| Отвечает текстом | Проходит рабочий процесс по фазам |
| Факты часто выдуманы | Факт без дословной цитаты **отбрасывается** |
| Не помнит, что делал | Журнал шагов на диске, append-only |
| Нельзя остановить и продолжить | `pf resume` продолжает с сохранённого места |
| Неизвестно, сколько стоило | `pf cost` показывает расход по ролям |

## Быстрый старт

Требования: **Python 3.11+**, **Ollama** с локальной моделью. Ни ключей,
ни внешних сервисов не нужно.

```bash
# 1. Установить зависимости
make setup

# 2. Скачать модель (4.7 ГБ)
ollama pull qwen2.5:7b

# 3. Проверить, что всё живо
make doctor

# 4. Поставить задачу
pf run "Почему падает удержание у мобильного тарифа и что с этим делать?"
```

Если `pf` недоступен после `make setup`, используйте `python -m pf.cli ...`.

## Команды

| Команда | Что делает |
|---|---|
| `pf run "вопрос"` | Поставить задачу и провести работу до стратегии |
| `pf resume` | Продолжить сохранённую сессию с того же места |
| `pf answer "текст"` | Ответить на вопрос, который задал агент |
| `pf stop` | Остановить сессию |
| `pf log` | Показать журнал шагов с основаниями и стоимостью |
| `pf cost` | Показать расход: по итогу и по ролям |
| `pf sources "запрос"` | Показать, какие источники агент найдёт |
| `pf sessions` | Список сохранённых сессий |

## Как устроен

### Четыре слоя знаний (раздельно, как требуется)

| Слой | Где | Что внутри |
|---|---|---|
| Постоянные инструкции | `prompts/roles/*.md` | Правила работы каждой из девяти ролей |
| Методические знания | `methods/*.md` | Методики: факт/гипотеза, варианты, стратегия, план проверки |
| Материалы проекта | `project/` | Данные конкретной задачи |
| Состояние задачи | `state/`, `journal/` | Текущая фаза, результаты, журнал шагов |

### Девять ролей

`intake` (постановка задачи) → `planner` (план исследования) →
`collector` (сбор источников) → `analyst` (разбор) → `options` (варианты) →
`redteam` (критика) → `strategy` (стратегия) → `keeper` (фиксация решения) →
`router` (маршрутизация).

Каждая роль — файл промпта и схема ответа. Содержание правится без
перезапуска.

### Проверка оснований — главный механизм честности

Модель может написать связный и правдоподобный текст. Она не может
процитировать статью, которой нет. Поэтому каждое утверждение проверяется:

1. **Цитата** должна дословно встречаться в исходном тексте статьи.
2. Если цитаты нет — проверяется, что утверждение собрано из слов
   указанного абзаца (порог 80 %).
3. **Источник должен быть релевантен задаче**: настоящая цитата из
   посторонней статьи основанием не является.

Что не прошло проверку — попадает в журнал как отклонённое основание с
причиной. Это видно пользователю, а не прячется.

### Источники

Локальный снимок Википедии: 7 966 статей из 10 разделов
(`data/wiki/`, лицензия CC BY-SA 4.0, атрибуция — в `data/wiki/SOURCE.md`).
После удаления дублей по заголовку в поиск попадает 7 733 статьи.
Поиск — TF-IDF, индексация занимает секунды, тяжёлые модели не нужны.

### Продолжение после перерыва

Состояние — обычный JSON на диске:

```bash
pf run "вопрос"      # работает до фазы, где нужен человек
pf answer "ответ"    # отвечаем
pf resume            # продолжает
```

Работа продолжается и в новом чате: состояние лежит в файле, а не в памяти
процесса.

## Модель

По умолчанию — локальная `qwen2.5:7b` через Ollama: без ключей и без
затрат. Модель поменьше (`qwen2.5:3b`) тоже работает, но приводит цитаты
реже — тогда основания проверяются по покрытию абзацем.

Поддерживается любой OpenAI-совместимый API:

```bash
cp .env.example .env
# в .env: PF_LLM_PROVIDER=openai, PF_LLM_BASE_URL=..., PF_LLM_API_KEY=..., PF_LLM_MODEL=...
```

## Стоимость

Считается в **условных единицах**: 1 единица = 1 000 000 токенов. Это объём,
который легко перевести в деньги по тарифу модели. `pf cost` показывает
сумму и разбивку по ролям.

Полный прогон демонстрационной задачи на `qwen2.5:7b` — около **13 000 токенов**
(0.013 единицы) и **~100 секунд**.

## Ограничения

Честно о том, что агент **не** умеет:

- **В корпусе нет данных об оттоке абонентов.** Википедия даёт рыночный
  контекст (тарифы, конкуренция, абонентская база операторов), но не
  внутреннюю телеметрию. Агент это называет как пробел — именно так и должно
  работать.
- **Модель 7B — среднего размера.** Содержание бывает бедным: варианты
  различаются не всегда ярко. Увеличение размера модели — первое, что
  стоит попробовать.
- **Поиск только по локальному корпусу.** Веб-источники не подключены.
- **Проверка цитат ловит пересказ, а не ложь по смыслу.** Цитата из
  настоящей статьи проходит. Поэтому проверяется ещё и релевантность
  источника задаче.

## Разработка

```bash
make test        # 51 тест, без обращения к модели
make lint        # ruff
make format      # ruff format
make typecheck   # mypy --strict
make ci          # всё вместе
```

Тесты делятся на две группы: детерминированные (проверка оснований, схем,
состояния — идут без модели) и те, что бьют по живой модели (`make test-slow`).
