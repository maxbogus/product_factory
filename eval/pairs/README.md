# Набор пар «дословно, но не по месту»

> **Зачем.** Проверка оснований лексическая: она ловит выдуманную цитату, но
> пропускает честную цитату, поставленную не к тому утверждению (`D-19`).
> Прежде чем ставить модель эмбеддингов, надо измерить, ловит ли она этот
> класс ошибки. Измерять не на чём, пока нет размеченного набора, — поэтому
> набор лежит здесь (`D-37`, `T-36`).

## Состав

`out_of_place.jsonl` — 60 пар, по строке на пару:

| Поле | Что это |
|---|---|
| `id` | `p-001`…`p-060`, уникальный |
| `claim` | Утверждение, которое собралось опираться на цитату |
| `quote` | Цитата: **обязана** лежать дословно в абзаце источника |
| `source_id`, `paragraph` | Источник и номер абзаца — чтобы проверка дословности была машинной |
| `label` | `in_place` (цитата подтверждает) или `out_of_place` (дословная, но не по месту) |
| `kind` | `real` (взято из журнала прогона) или `synthetic` (собрано из своих же данных) |
| `why` | Почему метка такая — словами. Метка без причины не проверяется |

Половины: 30 `in_place` / 30 `out_of_place`. Две модели поведения в наборе:

- **пересказ** (`in_place`, `synthetic`): утверждение передаёт ту же мысль без
  чисел — «Tele2 почти сорок миллионов абонентов» против строки «значение:
  38.9». Честное подтверждение, которое лексика легко теряет;
- **чужая строка** (`out_of_place`): дословная цитата другого показателя,
  оператора или периода. Ровно тот случай, ради которого затевается замер.

## Разбиение train/test

Порог флага калибруется на половине `train` и замораживается, метрики
считаются на `test` (`pf.semantic_bench.split_of`). Деление идёт **по порядку
внутри класса**, а не по чётности номера: иначе одна половина оказалась бы
целиком из честных пар, и точность на `test` не проверялась бы вовсе. Так и
вышло на первом прогоне — это записано в журнале сессии.

## Что набор намеренно не проверяет

- **Строки без названия показателя.** В `cbr_key_rate_2026_q1.csv` строка —
  это «дата: 13.01.2026, значение_процентов: 78.7913»: показатель назван
  колонкой, а не текстом. Никакая близость текста такую строку не сопоставит
  с утверждением «ключевая ставка 13 января 2026 года», поэтому в наборе таких
  пар нет. Для них работает расчёт по якорю строки (`D-35`, `D-36`), а не
  близость.
- **Выгрузки `knowledge/raw/`.** Они по `D-29` выше «требует проверки» не
  поднимаются, и понижать там нечего: флаг имеет смысл только для оснований,
  которые могли бы стать подтверждёнными.
- **Провенанс в цитате.** Хвост «источник: https://…» из оценки близости
  исключается: иначе сходство зависело бы от длины адреса (то же правило, что
  в отборе строк, `sources._row_score`).

## Как пополнять

1. Цитата берётся из источника целиком (абзац), а не переписывается.
2. Метка ставится вручную; `why` объясняет, почему цитата подтверждает
   утверждение или не подтверждает.
3. `uv run pytest tests/test_semantic_bench.py -k gate -q` — проверка
   дословности и полноты набора.
4. Пополнили набор → замер надо повторить: снимок замера хранит хеш набора, и
   `-k verdict` покраснеет, если замер отстал (`D-28` как образец).
