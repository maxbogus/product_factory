# Второй проект: переносимость доказана, а не обещана

Это материалы **другого домена** — кардиология и профилактика артериальной
гипертензии. Ничего в `src/` для него не меняется: домен задаётся файлом
`project2/domain/entities.yaml` (`PF_DOMAIN_DIR`), материалы читаются тем же
`pf.materials.scan_materials`, основания проверяются тем же `pf.ground`, а
документ собирается тем же `pf.artifacts.build_document`.

Доказательство — `tests/test_portability.py` (`-k second_project`):

1. материалы второго проекта читаются (`scan_materials`);
2. второй домен берётся из файла (субъекты и термины кардиологии, телекома
   больше нет) и `pf.corpus.is_domain_query` видит его;
3. основания проверяются: дословная цитата подтверждается, а утверждение с
   числом на материале **без цифр** получает «нет данных», а не
   «подтверждено»;
4. отчёт и документ строятся тем же путём из журнала («сохранённые ответы
   ролей» — живой прогон для этой проверки не нужен);
5. `git status -- src/pf` пуст: переносимость не потребовала ни одной правки
   кода.

## Чего здесь нет

Живого прогона на модели и `RESULT.md` этого проекта. Это честная граница:
тест доказывает **механику** (материалы → основания → отчёт), а не качество
стратегии на новом домене. Документ собирается тем же
`pf.artifacts.build_document`, когда прогон будет выполнен.

Здесь только данные — ни одного имени субъекта в `src/`, как требует гейт
`tests/test_no_entity_names.py` (`-k entity_names`).
