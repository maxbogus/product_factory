# Материалы проекта

Здесь — данные конкретной задачи: исходные материалы, документы, таблицы,
ссылки на разрешённые источники.

Это третий слой знаний (постоянные инструкции → методики → материалы
проекта → состояние задачи). Материалы проекта — то, что относится к
конкретной задаче и не должно попасть в инструкции.

## Правила

- Только открытые источники и собственные материалы.
- Персональные данные — не хранить.
- Каждый материал сопровождается ссылкой на источник.

| `data/cbr_key_rate_2026_q1.json` | Метаданные выгрузки ставки | Банк России |

## Как это используется

Материалы — третий слой знаний. Агент читает их **наравне** с корпусом
Википедии: те же идентификаторы `project/<файл>`, та же проверка
дословности цитаты. Строка таблицы становится цитатуемым абзацем, поэтому
на неё можно сослаться так же, как на абзац статьи.

Проверить, что агент видит материалы:

```bash
pf materials                    # что загружено: вид, абзацы, хеш
pf sources "отток абонентов"   # попали ли материалы в срез источников
```

## Границы

Это **рыночный контекст**, а не внутренняя телеметрия Мегафона.
Поквартальной динамики оттока по тарифам в открытых источниках нет, и
агент называет это пробелом. Цифры из разных источников — разные периоды
и разные операторы, поэтому они не складываются в один ряд.

Отдельно названы границы нового открытого ряда (`telecom_market_open.csv`):
это размер рынка и проникновение мобильной связи, а **не** проникновение
именно eSIM, **не** доля MVNO и **не** тарифы конкурентов — таких
структурированных открытых данных нет, и подменять одно понятие другим
нельзя (`D-31`).

## Как добавить свои материалы

Положите файлы в `project/` (`.md`, `.txt`, `.csv`, `.tsv`, `.json`,
`.pdf`, `.docx`, `.xlsx`) — агент подхватит их автоматически. Для
документов в формате PDF/DOCX/XLSX нужен набор библиотек:

```bash
uv sync --extra documents
```

Открытые данные обновляются скриптом:

```bash
uv run python scripts/fetch_open_data.py
```
