# Стратег Фабрики продуктов — карта проекта

> Этот файл — единая точка входа для ИИ-агента, работающего с репозиторием.

## Что это

ИИ-агент для руководителя цифрового продукта: от размытого запроса до
продуктовой и коммуникационной стратегии с проверяемыми основаниями, плюс
работа после решения (обязательства и пересмотр).

## Архитектура

```

  config.py      настройки из окружения (.env), без секретов в коде

  sources.py     отбор статей, нарезка на цитатуемые абзацы, ссылки
  materials.py   свои документы и таблицы: чтение, строки, метаданные
  analysis.py    расчёты по данным: median, mean, изменение, CAGR
  report.py      отчёт по прогону: числа, расход, границы замера
  review.py      пересмотр выводов: записанный хеш данных против текущего файла
  knowledge_store.py хранилище знаний: сырые выгрузки и манифест
  ground.py      ПРОВЕРКА ОСНОВАНИЙ: цитата должна быть дословной
  hypotheses.py  вердикт гипотезы: support/refute/unknown по основаниям
  lexical.py     лексическая близость: леммы, точные термины, числа, распознавание
  sanitize.py    чистка текста для сравнения: провенанс, колонки, разметка
  quantities.py  величины: слова-числа, шкала, единица, модификатор

  canonical.py   сравнение по полям и степень поддержки вместо порога покрытия
  synonyms.py    словарь близости: группы взаимозаменяемых понятий
  lexicon.py     словарь из файла и очередь распознания незнакомых слов
  llm.py         клиент модели (Ollama / OpenAI-совместимый), ретраи
  schemas.py     схемы ответа: ограничения на форму и содержание
  roles.py       реестр ролей: промпт + схема
  knowledge.py   слой знаний: методы и скилы, подставляемые в роли
  workflow.py    конечный автомат: фазы, проверка, журнал, хуки
  hooks.py       хуки: действия по событиям (правила из hooks/*.yaml)
  web.py         внешние источники: поиск в интернете и статус «требует проверки»

  journal.py     append-only журнал шагов, учёт стоимости
  state.py       состояние сессии: сохранение и продолжение
```

## Четыре слоя знаний (раздельно, как требует бриф)

| Слой | Путь | Что правится |
|---|---|---|
| Постоянные инструкции | `prompts/roles/*.md` | Поведение каждой роли |
| Методические знания | `methods/*.md` | Методики работы |
| Материалы проекта | `project/` | Данные задачи |
| Словарь близости | `knowledge/lexicon/` | Синонимы и очередь распознания слов |
| Состояние задачи | `state/`, `journal/` | Ход работы (не коммитится) |

## Фазы рабочего процесса

```
INTAKE → PLANNING → ROUTING → COLLECTING → ANALYZING → OPTIONS → REDTEAM → STRATEGY → KEEPER → DONE
```

Роли: `intake`, `planner`, `router`, `collector`, `analyst`, `options`,
`redteam`, `strategy`, `keeper`.

У каждой фазы есть роль — это проверяется тестом: фаза без роли молча
ничего не делает.

## Ключевые файлы

- `src/pf/ground.py` — механизм честности. Правится только вместе с тестами
  в `tests/test_ground.py`.
- `src/pf/lexical.py` — лексическая близость: леммы, точные термины,
  числа с допуском, распознавание слов. Тесты — `tests/test_lexical.py`.
- `src/pf/sanitize.py` — чистка текста **для сравнения** (провенанс, имена
  колонок, разметка, колонтитулы). Тесты — `tests/test_sanitize.py`
  (`-k sanitize`). Дословность проверяется по сырому тексту (`D-38`).
- `src/pf/quantities.py` — величины: слова → число, шкала, единица,
  модификатор «почти/более/менее». Тесты — `tests/test_quantities.py`
  (`-k quantities`).
- `src/pf/periods.py` — периоды как интервалы в шкале года: год, квартал,
  дата, месяц, «с 2013 по сентябрь 2019». Правило `D-34` одно на весь
  репозиторий; `analysis._period_key` делегирует сюда. Тесты —
  `tests/test_analysis.py` (`-k period_order`), `tests/test_canonical.py`.
- `src/pf/canonical.py` — каноническое сравнение: поля (понятие показателя,
  субъект, регион, период, величины, термины, отрицание, опора) дают доли,
  итог — **число** от 0 до 1; порог — настройка `claim_support_threshold`.
  Правится вместе с `tests/test_canonical.py` (`-k fields`) и замером
  `make tune-threshold` (`D-39`).
- `src/pf/semantic_bench.py` — замер семантики: набор пар, калибровка порога
  на train, метрики на test, гейт из четырёх критериев (`D-37`). Тесты —
  `tests/test_semantic_bench.py` (`-k gate` — T-36, `-k verdict` — T-37).
  Набор данных — `eval/pairs/out_of_place.jsonl`, протокол — рядом в README.
- `src/pf/lexicon.py` — словарь из файла и очередь распознания. Проверка
  оснований читает только `approved`; тесты — `tests/test_lexicon.py`.
- `src/pf/hypotheses.py` — правило вердикта гипотезы. `verdict_of` читает
  **подтверждённые** основания; направление и предмет — из `pf.lexical`.
  Правится вместе с `tests/test_hypotheses.py` (блок `-k verdict`).
- `src/pf/materials.py` — `scan_materials`: два корня (`project/` и
  `knowledge/raw/<дата>/`), происхождение материала, отчёт о пропуске.
  Правится вместе с `tests/test_materials.py` (блок `-k knowledge_store`).
- `src/pf/schemas.py` — ограничения на ответ. Новое поле → новый тест.
- `src/pf/analysis.py` — расчёты. Ряд — одна величина во времени; без
  группировки по рядам получаются бессмысленные величины.
- `src/pf/report.py` — отчёт по прогону. Раздел «чего замер не
  показывает» обязателен.
- `src/pf/corpus.py` — `DOMAIN_TERMS` и `STRONG_DOMAIN_TERMS`: словарь
  предметной области. При смене темы агента правится здесь.
- `prompts/roles/*.md` — 9 файлов, по одному на роль.
- `docs/TASKS.md` — индекс задач: фазы, SP, RICE, критерии приёмки.
  Гейт `make tasks-check`; карточки — `docs/tasks/`.
- `docs/HANDOFF.md` — состояние работы между сессиями; журнал —
  `docs/sessions/`.
- `docs/canon.py` — единственный источник чисел, которые называют
  `README.md` и `docs/DESCRIPTION.md`. Гейт `make docs-check`.
- `tests/test_documents_consistency.py` — заявления документов против кода:
  умолчания `.env.example` против `Settings.model_fields`, единая
  инструкция для `--extra documents`, `demo/BRIEF.md` про веб, README про
  цикл пересмотра, команды из README. Гейт `make ci`.
- `docs/decisions.md` — почему всё так.
- `docs/DESCRIPTION.md` — описание работы для сдачи (обновлять вместе с кодом).
- `docs/VIDEO_SCRIPT.md` — сценарий видеозаписи.

## Gotchas

- **Длинный контекст ломает модель.** `Workflow.CONTEXT_PASSAGES = 5` — не
  увеличивать без проверки: на 9+ абзацах локальная модель начинает
  возвращать «историю диалога» вместо JSON.
- **`extract_json` терпим к обёрткам**, но не к обрезанному ответу. Если
  пришло «JSON не закрыт» — поднимите `PF_MAX_TOKENS`.
- **Проверка оснований ловит пересказ, а не ложь по смыслу.** Поэтому
  дополнительно проверяется релевантность источника (`SourceBundle.is_relevant`).
- **Числа сверяются с допуском 0,1 для величин от единицы.** «77,3»
  подтверждает «77,26», а «78,0» — нет. Для малых величин абсолютный
  допуск не включается: 0,1 — половина от 0,2 (`src/pf/lexical.py`).
- **Синонимы расширяют понимание, но не ослабляют проверку.** Точные
  термины (числа, бренды, аббревиатуры) и добавленное отрицание
  проверяются строго. Словарь — данные: `knowledge/lexicon/synonyms.yaml`.
- **Незнакомое слово не теряется.** Оно пишется в
  `knowledge/lexicon/oov.jsonl` (append-only, в `.gitignore`), а
  `pf lexicon enrich` предлагает понятие. Записи `proposed` в проверке
  не участвуют — подтверждает человек.
- **Внешний источник не бывает подтверждённым.** Цитата проверяется по
  скачанной странице, но статус — «требует проверки». Такие основания
  идут в отчёт отдельным разделом, а не в «Отклонённые».
- **Лимит ответа говорится модели заранее.** Иначе она пишет длинный
  JSON и получает обрезок; ограничения задачи передаются всем ролям
  (`_prompt_extras`).
- **Ollama режет промпт по `num_ctx`.** Раньше окно не задавалось, Ollama
  брал своё (4096), и на сохранённых журналах 56 шагов упирались ровно в
  4096 токенов промпта: начало контекста отбрасывалось молча. Теперь окно
  передаётся явно (`PF_OLLAMA_NUM_CTX`, по умолчанию 12288 — выбрано
  замером), а признак обрезки пишется в `detail["context"]` шага и в отчёт.
  На карте меньше 8 ГБ верните 8192: при 8192 `analyst` и `strategy` снова
  упрутся, зато KV-кэш вдвое меньше (`docs/decisions.md`, D-20).
- **Числа плана и обязательств сверяются с расчётами, а не с основой слова.**
  `Workflow._check_plan_numbers` берёт из плана и обязательств только
  величины с единицей (%, п.п., млн, руб.) и требует расчёт **того же**
  показателя; сроки («3 месяца») величиной не считаются. Показатель
  расчёта берётся из строки `#rowN` (`sources.indicator_of_citation`), а не
  из имени метрики: имя — заголовок материала. Замечания попадают в
  `rejected_details`, но подсказку модели не запускают.
- **Правило основ одно.** `pf.lexical.stems` и `pf.lexical.significant_words`;
  `sources._stems` и `Workflow._stems` делегируют туда. Своя копия регэкспа
  уже пропускала подмену показателя по слову из скобок.
- **Агрегат подтверждается расчётом по имени, а не строкой источника.**
  `sources._aggregate_by_name` ищет среди расчётов агента (`SourceBundle.metrics`,
  передаются из `Workflow.collect_sources`) метрику, чьё имя названо в
  основании — и показатель, и вид сводки, — сверяет значение и пересчитывает
  его по `inputs`. Среднего нет ни в одной строке таблицы, поэтому требовать
  дословности значило гарантировать отказ (D-35). Правило узкое: без входов,
  при другом числе или другом показателе отказ остаётся.
- **Повтор уже заданного вопроса не останавливает работу.**
  `Workflow.human_question_to_stop` снимает остановку, только если этот вопрос
  уже задавали **и на него ответили**; иначе модель, повторив вопрос, держала
  бы сессию вечно (так и вышло в `demo-v11`). Новый вопрос по-прежнему
  останавливает.
- **Строка таблицы отбирается по своим полям, а не по длине текста.**
  `sources._row_score`: показатель ×2, субъект ×1, прочее содержание ×0.5;
  провенанс (`источник`, `url`) из оценки исключён — иначе порядок строк
  задаёт длина URL. Доменный добор — только для строки, чей показатель
  называет объект отрасли, и с фиксированным баллом. Ничьи разрешает
  порядок источника.
- **Критерий приёмки из индекса должен выбирать все тесты задачи.**
  `-k numbers` не выбирает `test_..._number_...`: одно слово и его
  множественное число — разные подстроки. Красный прогон обязан показать
  «5 failed», а не «1 selected».
- **Ответ не обязан влезать в окно — это ошибка настроек.**
  `PF_MAX_TOKENS >= PF_OLLAMA_NUM_CTX` роняет создание настроек: иначе
  обрезка гарантирована, а выглядит как «модель ответила».
- **Вывод проверяется как факт.** `Workflow._sources_of` собирает ссылки из
  `product.evidence`, `communication.promise_grounding` и
  `commitments[].basis`; статус оснований вывода пишется в журнал шага
  (`detail["conclusion_check"]`). Гейт `conclusion-evidence-is-grounded`
  покраснеет, если проверка снова начнёт смотреть только в факты.
- **Основания вывода считаются по уникальным строкам источника.**
  `pf.ground.tally_grounds` схлопывает ссылки на один якорь и берёт худший
  вердикт: повтор подтверждённой цитаты не перекрывает отказ по той же
  строке. Шаг пишет ключи в `conclusion_check["grounds"]`, а
  `report._collect_conclusion` объединяет стратегию и решение, а не
  складывает их счётчики. Старый журнал без ключей при наличии отказов
  называется «записей» — распределить отказы по повторам нечем
  (`docs/decisions.md`, D-21).
- **Замер проверки воспроизводится харнессом.** `make replay` повторяет
  проверку на сохранённых результатах ролей (данные те же, меняется только
  код) и гоняет шесть контрольных проб; снимок (`--json`) сравнивается с
  прежним (`--compare`) по вердиктам, а не по счётчикам. Харнесс выключает
  очередь распознания на время замера: реплей не должен оставлять следов.
- **Документ демонстрации обязан отвечать на вопрос.** Раздел «Вывод»
  собирается из журнала (`pf.report.conclusion_markdown`), а не пишется
  руками: иначе он разойдётся с прогоном. `make demo-doc SESSION=...`.
- **Тесты не пишут в `state/` и `journal/`.** Каталоги подменяются на
  `tmp_path` в `tests/test_scenarios.py`; иначе после `make test` в дереве
  остаются `session-scenario-*` файлы.
- **Пустые цитаты и пустые `source_id` не роняют шаг**, но и не считаются
  основанием: они попадают в `rejected_details`.
- **Обработчик eval-кейса не должен содержать подстроку, которую ищет кейс.**
  `D-05` возвращал «Закрыть направление» при любом поведении схемы, и кейс не
  мог упасть. Теперь текст приходит из отказа схемы, а запасной текст
  обработчика искомой подстроки не содержит. Регресс —
  `tests/test_eval_cases.py::test_cases_d05_d06_go_red_without_pole_check`.
- **Полюса вариантов проверяются по названиям, а не по маркерам.** Маркер — это
  утверждение модели о своём ответе; в двух сохранённых прогонах из 25 он стоял
  при наборе без такого варианта. Маркеры выводятся из названий
  (`Variants._poles`), формулировки — константы `src/pf/schemas.py`, а не
  данные `knowledge/lexicon` (`docs/decisions.md`, D-23).
- **Выгрузка — знание, но не основание.** `knowledge/raw/<дата>/` читается как
  материалы (`PF_INCLUDE_KNOWLEDGE_RAW`), но её основание проходит
  `ground.mark_external`: цитата проверяется дословно, а статус не поднимается
  выше «требует проверки». Расчёт по строке выгрузки тоже. Копия того же файла
  в `project/` не второй источник — она называется в пропуске
  (`pf.materials.scan_materials`), а не удваивает контекст (`D-29`).
- **Пропуск материала виден.** `scan_materials` возвращает `skipped` с причиной,
  `pf materials` печатает раздел «Пропущено». Молчаливый пропуск PDF без
  `pdfplumber` выглядел как отсутствие документа в проекте.
- **Тесты не читают настоящие выгрузки.** `tests/conftest.py` уводит
  `knowledge_dir` в `tmp_path` на весь набор. Новый тест, который не подменил
  каталог, иначе зависел бы от содержимого репозитория.
- **Вердикт гипотезы ставит код.** `pf.hypotheses.verdict_of` выводит
  `supported` / `refuted` / `unknown` из **подтверждённых** оснований, а
  `Claim.verdict` из ответа модели отбрасывается валидатором. Направление и
  предмет берутся из `pf.lexical.polarity` / `topic_words` — то же правило, что
  у противоречий в фактах (`D-30`).
- **Хеш данных — запись, а не вывод.** У материалов проекта хеш лежит в
  `<файл>.meta.json`, у выгрузок — в манифесте. `pf review` сравнивает
  записанный хеш с текущим файлом и говорит «требует пересмотра», а не
  «вывод неверен»: хеш меняется и при косметической правке. «Хеш не записан»
  — отдельное состояние: сравнивать нечем, и это не «не изменилось».
  Правится вместе с `tests/test_review.py` (D-33).
- **Открытого ряда оттока нет — и это названо.** Ни поиск по Википедии, ни
  годовой отчёт за 2025 год (86 страниц), ни сайты операторов числа оттока не
  дают; тарифы конкурентов недоступны (МТС 401, T2 503, Билайн рисует цены
  скриптами). Прокси «чистое изменение базы» как отток не вводится: это
  подмена понятия (`docs/decisions.md`, D-31). Файлы данных — только с
  `url`, `retrieved`, `note`, `sha256`; проверка — `tests/test_demo_data.py`.
- **Квартал — часть года, а не число из цифр периода.** `analysis._period_key`
  разбирает «1 кв. 2017», «2017-Q1», «Q1 2017», «I квартал 2017» одной
  ветвью до разбора по цифрам; ключ квартала — `год + квартал / 5`, поэтому
  год идёт раньше своих кварталов, а четвёртый — раньше следующего года
  (D-34). Пока квартал склеивался в число, «1 кв. 2017» давало `12017`,
  первый квартал 2018 года вставал раньше четвёртого квартала 2017-го, и
  изменение считалось по случайному порядку строк. Правка — вместе с
  `tests/test_analysis.py` (блок «Порядок ряда по периоду», `-k period_order`).
- **Окно контекста делится между своими материалами и корпусом.** С четырьмя
  файлами данных окно из пяти абзацев занимали только строки таблиц.
  `SourceBundle._window` резервирует один слот корпусу (D-32); проверка —
  `test_window_reserves_slot_for_corpus` и
  `test_context_is_not_eaten_by_one_table`.
- **Журнал append-only.** Не переписывайте `journal/*.jsonl` — это след.
  Второй шаг с тем же номером журнал не принимает (`DuplicateOrdinalError`,
  T-32): дубль `ordinal` означает два запуска в один файл, и молча его
  записывать нельзя — отчёт посчитал бы основания дважды. Новый запуск
  берёт свободный id (`pf.cli._new_session_id`); проверка —
  `tests/test_state_journal.py -k duplicate_ordinal`.
- **Строка расчёта копируется из блока РАСЧЁТЫ вместе с разметкой.**
  `sources._calc_line_anchor` читает `[путь#rowN]` и `(формула)` из самой
  цитаты, якорь берётся оттуда, а разметка блока текстом источника не
  считается; показанное `%.4g` значение сверяется со строкой с допуском
  (D-36). Расхождение якоря в ссылке и в цитате — отказ. Проверка —
  `tests/test_sources.py -k calc_line_quote`.
- **`state/` и `journal/` в `.gitignore`.** Результаты работы — артефакт
  прогона, а не часть поставки.
- **Thinking-режим выключен явно** (`PF_OLLAMA_THINK=false`). У `qwen3` и
  `deepseek-r1` он включён по умолчанию: модель возвращает рассуждение
  вместо JSON, и разбор падает.
- **Веб-контекст отделён от локального** блоком «ВНЕШНИЕ ИСТОЧНИКИ»:
  у внешних источников другой статус подтверждения, смешивать нельзя.
- **Bing web по HTTP отдаёт мусор из чэша.** Рабочие каналы — RSS-ленты
  и Bing News; веб-выдача только запасная и фильтруется по теме.
- **MCP-серверы требуют `mcp==1.28.0`** (на 2.x декораторы `@app.list_tools`
  убраны) и живут в своём окружении; путь — `PF_MCP_DIR`.
- **Перевод не бывает основанием.** `pf.translate` кладёт перевод рядом с
  оригиналом, но цитата сверяется с источником: дословность — по оригиналу,
  для русской цитаты — по переводу, числа — **всегда** по оригиналу. Статус не
  поднимается выше «требует проверки»: `SupportStatus` не расширяется,
  `mark_external` не ослабляется (`docs/decisions.md`, D-27).
- **Кэш переводов обязателен.** Без него `make test` и `make replay` ходили бы
  в модель, и прогон перестал бы повторяться. Ключ — хеш **исходного** текста;
  числа сверяются и при чтении кэша, а непригодный перевод в кэш не пишется
  (D-28).
- **Требование языка одно на все роли.** Оно живёт в
  `Workflow._prompt_extras`, а не в девяти промптах: пока контекст был русским,
  его отсутствие было незаметно, а на английском материале модель отвечала
  по-английски — JSON с русскими ключами и английскими значениями.
- **Английский заголовок не проходит `_matches_terms`.** Фильтр в
  `pf.web.search_web` считает основы русских слов, поэтому английский канал
  идёт отдельной командой, а не в общем списке (D-26).
- **Порог флага «не по месту» калибруется по самому низкому честному
  пересказу** — и после этого не ловит ничего. Полнота 0,00 (TF-IDF) и 0,07
  (`rubert-base-cased`) при пороге 0,7: честный пересказ («почти сорок
  миллионов») и чужая строка того же домена лежат в одном диапазоне
  близости, поэтому «точность не падает» и «полнота ≥ 0,7» одновременно не
  выполняются. Это измерение, а не мнение: `make semantic-bench`, снимок
  `reports/semantic/2026-11-09-tfidf-rubert-sbert.json`, вердикт в `D-37`. Модели в
  `pyproject.toml` не добавлять: `D-09` в силе.
- **Аббревиатура короче четырёх букв не попадает в мешок слов.**
  `corpus._TOKEN_PATTERN` — `[а-яёa-z]{4,}`, поэтому «МТС» и «T2» в леммах не
  появляются вовсе. Измерено: 12 из 24 ложных отказов на наборе пар были
  именно этим — строка, начинающаяся с «оператор: МТС», отклонялась «термин не
  найден» при любом составе остальных слов. Точные термины разбираются своим
  токенизатором (`canonical.strict_terms`), и глобальный шаблон корпуса ради
  этого не меняется: он общий с TF-IDF.
- **Правило терминов одно, и оно читает сырой текст.** `strict_terms`
  вызывался **после** `for_comparison` (нижний регистр), и «мтс» переставало
  быть аббревиатурой: в проверке без цитаты терминов не было вовсе. Второе
  правило (`lexical._term_present`) искало `lemma('МТС')` в мешке слов, где слов
  короче четырёх букв нет, — и «МТС» не находился никогда. Теперь одно правило —
  `lexical.term_present` (целым словом, по сырому тексту), им пользуются и
  `canonical`, и `lexical` (`D-45`).
- **Цитата не переключает правило проверки.** Недословная цитата уводила
  проверку в лексическое покрытие с порогом 0.8, и верное утверждение
  отклонялось (`demo-v12`, МТС и Tele2). Теперь вид отказа назван
  (`Support.kind`), а `too_short`/`paraphrase`/`number_mismatch` проверяются
  полями. Выдумка не откатывается: `QUOTE_FALLBACK_KINDS` её не содержит.
- **Округление — это маска числа и сверка чисел вместе.** Маска одна
  подтверждала любое другое число: «99,99» и «77,26» после маски совпадают.
  Регресс держит существующий тест, а не новый.
- **Отказ называет свою причину.** `SourceBundle.absence_reason` различает
  «ссылки нет», «ввод человека», «источник вне среза задачи» и «источник не
  найден среди материалов»; `rejection_kind` смотрит причину, а не первое
  знакомое слово. В `cloud-deepseek-2` девять отказов из двенадцати были
  ссылкой на ввод человека, а попадали в «источник нерелевантен».
- **Ввод человека не выглядит источником.** Подпись `Ответ человека:` в
  контексте читалась моделью как заголовок документа. Теперь — «Ввод человека
  (не источник, на него нельзя ссылаться)»; схему `SourceRef` не ужесточали:
  иначе `roles.validate` перестал бы читать сохранённые журналы.
- **Смена классов отказов требует пересборки демо-документа.**
  `make demo-doc SESSION=...` перечитывает журнал; сам журнал не
  переписывается. Иначе `test_document_matches_its_journal` краснеет.
- **Основание решается числом, а не порогом покрытия.** `pf.canonical.score`
  даёт степень поддержки 0–1, `ground.verify_claim` сравнивает её с
  `PF_CLAIM_SUPPORT_THRESHOLD` (0,17). Порог заморожен замером
  (`make tune-threshold`), и тест `test_fields_threshold_is_frozen_by_measurement`
  краснеет, если поле или вес поехали, — тогда порог перезамеряется, а не
  подкручивается на глаз. Порог покрытия (`PF_CLAIM_MIN_OVERLAP`) остался
  признаком только для источника из одного предложения (`D-39`).
- **Год — период, а не величина; шкала — из шапки колонки.** «В 2016 году —
  27,4 млн» разбирается как две величины, и год не находился среди значений —
  честная пара отклонялась «величина 2016 не совпала». Теперь год проверяет
  `pf.periods`, даты вырезаются `mask_dates`, а «млн» берётся из `показатель`:
  без этого «почти сорок миллионов» против 38,9 проходило по случайности.
- **Скобка в названии метрики и в абзаце — разное.** В `показатель:
  абонентская база (консолидированная)` скобка примечание, её нельзя требовать
  от утверждения; в абзаце «(проникновение — более 130 %)» — это сам
  показатель. Два разных чтения: `_indicator_concepts` и `_passage_concepts`.
- **Таблица синонимов не кэшируется между вызовами.** Словарь подтверждает
  человек, и пополнение должно действовать сразу: с кэшем сценарий
  «подтверждённый синоним расширяет близость» оставался красным.
  перемежаются: одна половина оказывается целиком из честных пар, и точность
  на test не проверяется вовсе. Делить по порядку внутри класса
  (`pf.semantic_bench.split_of`) — на этом замер уже ошибался.
- **Чистка текста касается только сравнения, никогда — дословности.**
  `pf.sanitize.for_comparison` снимает url и имена колонок; `ground.find_quote`
  продолжает искать цитату в **сыром** тексте. Иначе чистка стала бы способом
  подтвердить пересказ (`D-38`, `test_sanitize_does_not_replace_verbatim_check`).
- **Числа не входят в мешок слов.** `words()` выбрасывает цифры и слова
  короче четырёх букв, поэтому числа разбирает `pf.quantities`, а не TF-IDF:
  совпадение числа (`27,4 млн` у 2016 и у накопленного итога 2019) выдавало
  себя за смысловое сходство и было прямой причиной утечки `p-032`.
- **Направление нормализации чисел одно — слова → число.** Цифры в пропись не
  переводятся: на наборе из 60 пар это +217 токенов к цитатам и потеря
  точности (`172,87` → «сто семьдесят две целых восемьдесят семь сотых»).
- **Идентификатор модели на хабе — не название из статьи.** `DeepPavlov/ruBERT-base`
  даёт 401, настоящий — `rubert-base-cased`; первый прогон `T-37` упал именно
  на этом. Зависимость, названная в решении, должна запускаться.



- **Служебные слова показателя вычитаются.** `pf.lexical.GENERIC_STEMS` /
  `indicator_stems`: по одному слову «период» расчёт по ключевой ставке
  становился «тем же показателем», и верные числа `7,39 млн` и `84,62 %`
  отклонялись словами «не совпадает с расчётом по показателю «Ключевая
  ставка…»». Число, названное вместе со ссылкой `[путь#rowN]`, подтверждается
  тем расчётом, на который ссылка указывает (`D-40`). Правило живёт вместе с
  `tests/test_success_criteria.py` (`-k foreign_indicator`).
- **Дословная цитата не отвечает, тот ли показатель подтверждён.**
  `Workflow._conclusion_topic` берёт показатель вывода из `expected_change` и
  `commitments[].metric` — **без** направления (текст действия упоминает любой
  показатель); `Workflow._ground_indicators` берёт показатель основания из
  строки таблицы. Несовпадение даёт потолок «подкреплено частично» в
  `pf.ground.conclusion_status(off_topic=...)` — правило одно на рабочий процесс
  и отчёт. Основания без названного показателя (абзацы статей) правило не
  судит; замер на пяти журналах дал одно срабатывание и ноль ложных понижений
  (`D-41`, `tests/test_conclusion_grounding.py -k indicator`).
- **Отчёт не выдаёт записи за основания.** Доля подписана «записей» (считается
  по записям, а не по уникальным ключам), одинаковые отказы схлопываются с
  `(×N)`, прогон без вывода начинается строкой «Прогон не даёт решения», шаги
  считаются по уникальным `ordinal`, а дубль номера печатается словами
  («журнал писался дважды»). Набор вариантов печатается с полюсами через
  `pf.schemas.pole_of` — второй копии списков названий нет (`D-42`, `D-43`).
- **Статус вывода несёт имя правила.** `pf.ground.CONCLUSION_RULE` —
  `unique-grounds+calc-line-demotion+indicator-cap` — пишется в журнал вместе со
  статусом. Меняете правило счёта оснований — меняйте имя; иначе отчёт не
  отличит запись прогона от текущей оценки. Журнал без имени подписывается «по
  правилу прогона», противоречие внутри журнала (строка отклонена на одном шаге
  и подтверждена в выводе) называется ключами, а перепроверка отправляется к
  `make replay` (`D-44`, `tests/test_report_conclusion.py -k stale_rule`).
- **Допущения вывода — не риски.** `ProductStrategy.assumptions` называет
  условия, при которых решение работает; риски живут в `adverse_effects`. Прогон
  текущим правилом без допущений печатает «Допущения вывода не названы», а
  унаследованный журнал не судится: поля тогда не было (`T-51`).
- **arXiv — отдельная команда, а не канал в `search_web`.** Общий фильтр
  релевантности считает основы русских слов, поэтому английские заголовки
  выпадали бы молча (`D-26`). `pf web --arxiv`, `SearchHit.peer_reviewed=False`,
  `src/pf/arxiv.py`, тесты `-k atom`.
- **`export` в оболочке агента переживает команду.** `export
  PF_LLM_PROVIDER=openai` для прогона на облачной модели остаётся в окружении и
  роняет `tests/test_llm_client.py` («qwen3:8b» против «deepseek-flash»).
  Прогон запускать как `env PF_LLM_PROVIDER=openai uv run pf run …`, а перед
  `make ci` проверять `printenv | grep PF_LLM`.
- **Кандидат добора — не основание.** `pf.hypotheses.plan_collection` ищет по
  неизвестным гипотезам и пробелам и ранжирует найденное близостью, но статус
  не поднимает и вердикт не меняет: иначе поиск сам себе выдавал бы
  подтверждение. Пробелы-противоречия не ищутся вовсе — возвращаются
  `not_collectable` с причиной. Остановку считает `pf.policy` (два пустых
  раунда), а не добор; `detail["collection"]` шага разбора и раздел отчёта
  называют исходы (`D-15`, `D-37`).
- **Потолок статуса за число без расчёта включён параметром.** Потолок есть в
  `pf.ground.conclusion_status` (`unsupported_numbers`) и входит в имя правила
  (`unsupported-number-cap`), но `_check_plan_numbers` считается **после**
  проверки оснований шага, поэтому связка «замечание → статус» — отдельная
  задача `T-48b`. Пока она не сделана, журнал пишет `unsupported_numbers: 0`,
  и это значит «не проверяли», а не «всё сошлось».

## Как ведётся работа

Работа идёт сессиями по 1–2 задачи. Порядок:

1. `docs/HANDOFF.md` — где остановились и что дальше.
2. `make next-task` — 1–2 задачи с наибольшим RICE из `docs/TASKS.md`.
3. Взять карточку `docs/tasks/<ID>.md` (для задач от 3 SP), статус в
   индексе → `🔄`.
4. **Сначала падающий тест**: критерий приёмки из индекса обязан краснеть
   до работы.
5. `make ci` зелёный → статус `✅`, в карточке `**Доказательство:**` с
   путём к тесту, который это держит.
6. `docs/sessions/<дата>-session-N.md`, обновить `docs/HANDOFF.md`,
   записать шаг в `~/.cline/memory/ml-sessions.jsonl`, коммит.

Числа, которые называют документы, живут в `docs/canon.py`. Меняете число в
коде — сначала `make canon` (он сверит с деревом), потом документы;
`make docs-check` не даст им разойтись.

## Проверка перед коммитом

```bash
make ci
```
